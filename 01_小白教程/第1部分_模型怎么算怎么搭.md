# 农业生态系统过程模型 · 小白教程
## 第一部分:模型到底"怎么算"、又是"怎么搭"出来的

> 写在前面:这份教程默认你**没有**数学或编程基础,只要会"代数 + 一点点指数"就能看懂。
> 每个概念我都先用生活里的东西打比方,再给一个能跟着算的小例子,最后才出现公式。
> 看到公式不要慌——每个字母我都会告诉你是什么意思。

---

## 0. 我们到底在聊什么?

农学里有一类软件,你输入"这块地的天气、土壤、什么时候播种施肥",它就能算出"一年后土壤里还剩多少碳、庄稼能收多少、排了多少温室气体"。这类软件就叫**过程模型(process model)**,代表有 **DNDC、RothC、CENTURY、APSIM、DSSAT**。

很多人把它当"黑箱":数据丢进去,结果吐出来,不知道里面发生了什么。这份教程就是带你**把黑箱拆开**,看清里面三件事:
1. 它用什么**公式**描述土壤和庄稼;
2. 计算机怎么把这些公式**算出来**;
3. 这堆公式怎么变成你能点鼠标运行的**软件**。

---

## 1. 第一个大比方:模型 = 一个"会推演的食谱"

想象做菜的食谱:"水烧到 100℃ → 下面 → 煮 3 分钟 → 捞出"。食谱的本质是**"当前状态 + 规则 → 下一个状态"**。

过程模型一模一样,只不过它的"规则"是科学定律,它推演的不是面条,而是**土壤里的碳、氮、水,和庄稼的生物量**。给它今天的状态(土壤有多少碳、多热、多湿),它用规则算出明天的状态,然后明天再算后天……一天一天推下去,几年的变化曲线就出来了。

**记住这句话**:模型干的事,永远是"今天的状态 + 规则 → 明天的状态",重复成千上万次。

---

## 2. 核心思想:把土壤看成"一个浴缸"

这是整份教程最重要的一张图,看懂它,后面全通。

把土壤里的碳想象成**浴缸里的水**:

```
        落叶、秸秆(进水管)
              │
              ▼
        ┌───────────┐
        │  浴缸里的水 │  ← 这就是"土壤碳"
        │  (碳的总量) │
        └───────────┘
              │
              ▼
        微生物呼吸排出 CO₂(出水管/下水道)
```

- **浴缸里的水量** = 我们关心的东西,专业叫**状态变量(state variable)**。土壤碳、土壤氮、土壤含水量、庄稼生物量,都是状态变量。
- **进水管和出水管** = 让水量变化的过程,专业叫**通量(flux)**。落叶掉进来是进水,微生物把碳分解成 CO₂ 跑掉是出水。
- **一条铁律**:水不会凭空出现或消失。**今天的水 = 昨天的水 + 流进来的 − 流出去的**。这叫**质量守恒(mass conservation)**,是所有模型的地基。

写成一句"数学话"就是:

> **碳的变化速度 = 流进来的速度 − 流出去的速度**

如果你愿意看符号,它长这样(`dC/dt` 就读作"碳 C 随时间 t 的变化速度",别被吓到,它就是"水位上升/下降的快慢"):

```
dC/dt = 进水 − 出水
```

---

## 3. 第二个比方:为什么"东西越多,消失得越快"?

现在问一个关键问题:出水管的水流多大?

直觉:浴缸里水越多,水压越大,下水道排得越快。微生物分解碳也一样——**土壤里碳越多,微生物食物越多,分解(排 CO₂)就越快**。

所以"出水速度"正比于"现有的碳量":

```
出水 = k × C
```

- `C` = 现在的碳量(浴缸水位);
- `k` = 一个"水管粗细"系数,叫**分解速率常数(decomposition rate constant)**。`k` 越大,排得越快。

把它代回上一节,得到模型里**最核心的一个公式**(叫"一阶衰减/first-order decay"):

```
dC/dt = 进水 − k × C
```

**跟着算一个小例子**(假设暂时没有进水):
- 浴缸里有 100 单位碳,`k = 0.1`(意思是每天排掉现有量的 10%)。
- 第 1 天:排掉 100 × 0.1 = 10,剩 90。
- 第 2 天:排掉 90 × 0.1 = 9(注意!不是 10 了,因为水位降了),剩 81。
- 第 3 天:排掉 81 × 0.1 = 8.1,剩 72.9……

你发现没有:**每天排掉的绝对量在变小**(10 → 9 → 8.1),因为水位在降。这条曲线就是"指数衰减",像手机电量越低掉得越慢。

一个有用的数字:`1/k` 大约就是"这个库换一遍的时间",叫**周转时间(turnover time)**。`k=0.1` 时,大约 10 天换一轮。

---

## 4. 加一个"调光器":温度和水分

上面假设微生物一直全速干活。但你知道:**冬天微生物偷懒,太干太涝也偷懒**。所以模型给出水管加了几个"调光器",每个调光器是一个 0~1 之间的折扣:

- **温度调光器 f(T)**:冷的时候接近 0(几乎不分解),暖的时候接近 1(全速)。
- **水分调光器 f(W)**:太干接近 0,太涝也接近 0,湿度刚好才接近 1(像一个钟形,中间高两边低)。

把这些折扣**乘**上去:

```
dC/dt = 进水 − [ k × C × f(T) × f(W) ]
```

**为什么是"乘"而不是"加"?** 因为只要有一个条件极端(比如结冰,f(T)≈0),整个分解就该停——乘法里只要一个因子是 0,结果就是 0。这正好符合"任何一个限制条件卡死,过程就停"的现实。这个"潜在速率 × 一串折扣 = 实际速率"的套路,叫**乘性限制因子框架(multiplicative limiting-factor framework)**,所有过程模型都用它。

**小例子**:潜在分解 `k×C = 10`,今天有点冷 f(T)=0.5,湿度刚好 f(W)=1.0 → 实际分解 = 10 × 0.5 × 1.0 = 5。冷天打了对折,合理。

> 这里也藏着"农学家的价值":这些 f(T)、f(W) 的具体形状,就是科学家把农学常识"翻译"成的数学。如果你发现某个模型在"极端暴雨导致土壤板结"时 f(W) 算得不对,改这个函数,就是你能做的科研。

## 5. 计算机到底怎么"算"出来?——一步一步往前挪

这是小白最困惑的地方。上面那个公式 `dC/dt = ...`,在数学上**根本解不出一个干净的公式**(因为每天的温度、湿度都在乱变,太复杂)。那计算机怎么算出 100 年后的碳?

答案出乎意料地"笨":**走楼梯**。

计算机不会高等数学,它只会加减乘除。于是它把"100 年"切成一天一天(甚至一小时一小时),然后:
- **今天**:已知碳量 = 100,算出今天的变化速度 dC/dt = −5(每天减 5)。
- **明天的碳量** = 今天的碳量 + 今天的速度 × 1 天 = 100 + (−5) = 95。
- **后天**:用 95 重新算速度,再往前挪一步……

写成公式(这就是大名鼎鼎的**显式欧拉法 / explicit Euler method**,听着唬人,其实就是上面这句话):

```
明天的碳 = 今天的碳 + (今天的变化速度) × (一天)
```

计算机疯狂重复这个简单加法几百万次,把每天的结果连起来,就画出了一条平滑曲线。

**记住**:模型的结果**不是"解方程"解出来的,是用极小的步子一步步"挪"出来的**(专业叫"数值积分/迭代")。

**两个小白也该知道的坑**:
1. **步子不能太大**。如果一步迈一年,可能"用力过猛"算出负的碳量(不合物理)。所以一般用"一天"这种小步子。
2. **快慢过程要分开走**。土壤分解很慢(日步够),但下雨后的反硝化很快(得用小时步)。DNDC 就是把快过程单独用小时步算,这叫**算子分裂(operator splitting)**——好比炒菜时"大火快炒"和"小火慢炖"分开处理。

## 6. 完整跑一遍:RothC 的"五个浴缸"(带手算)

光说一个浴缸太简单。真实的土壤碳模型有**好几个浴缸**,因为碳有的好分解、有的难分解。最经典、最适合入门的是英国的 **RothC** 模型,它有**5 个浴缸**:

| 浴缸 | 是什么(打比方) | 排水快慢 k(每年) |
|---|---|---|
| **DPM** | 易分解植物物料(嫩叶、糖分,微生物最爱) | **10**(超快) |
| **RPM** | 难分解植物物料(秸秆纤维) | **0.3**(慢) |
| **BIO** | 微生物自己的身体 | **0.66** |
| **HUM** | 腐殖质(变得很稳定的老碳) | **0.02**(极慢) |
| **IOM** | 惰性碳(几乎永远不动) | 不分解 |

`k` 差距巨大:DPM 的 10 对 HUM 的 0.02,差了 500 倍——这就是为什么有的碳几个月就没了,有的能在土里待几百年。

**几个浴缸之间还有水管连着**:DPM、RPM 分解后,一部分变成 CO₂ 跑掉,剩下的流进 BIO(微生物)和 HUM(腐殖质)两个缸。流进 BIO 和 HUM 的比例固定是 **BIO : HUM = 0.46 : 0.54**。

### 跟着官方例子手算(这是你能验证自己理解的金标准)

RothC 官方文档给了一个月的真实计算。假设这个月的三个调光器(温度 a、水分 b、覆盖 c)乘起来 = **0.3561**,月步长是 1/12 年。看 DPM 这个缸:

> 这个月"有效作用时间" = 0.3561 × (1/12) = 0.029675 年
> 剩下的 DPM = 0.1533 × e^(−10 × 0.029675)
>            = 0.1533 × e^(−0.29675)
>            = 0.1533 × 0.7432
>            = **0.1140**

翻译成人话:`e^(−0.297) ≈ 0.743`,意思是"这个月底还剩 74.3%,被分解掉了约 25.7%"。0.1533 的 74.3% 就是 0.1140。

同样的算法套到另外三个缸(注意它们 k 不同,所以剩得多少不同):

| 缸 | 月初 | 算式 | 月末 |
|---|---|---|---|
| DPM(k=10) | 0.1533 | ×e^(−10×0.3561/12) | **0.1140** |
| RPM(k=0.3) | 4.4852 | ×e^(−0.3×0.3561/12) | **4.4455** |
| BIO(k=0.66) | 0.6671 | ×e^(−0.66×0.3561/12) | **0.6542** |
| HUM(k=0.02) | 25.8576 | ×e^(−0.02×0.3561/12) | **25.8423** |

看出规律没?**k 越大掉得越多**:DPM(k=10)一个月掉了 1/4,而 HUM(k=0.02)几乎纹丝不动。如果你写代码能复现出这四个数,就说明你真的懂了。

(还有一个小公式:那个"惰性碳"IOM 没法直接测,用经验式 `IOM = 0.049 × 总碳^1.139` 估出来。)

## 7. 庄稼是怎么"长"出来的?(作物模型)

土壤碳讲完,换个浴缸——这次算庄稼的**生物量**怎么积累。作物模型(DSSAT、APSIM)有四个核心动作,我逐个打比方:

### (1) 攒"积温":庄稼用温度计时,不用日历(GDD)
庄稼发育快慢不看过了几天,看**攒够了多少热量**。好比攒钱买东西——不是"到某天就能买",而是"攒够钱才能买"。每天攒的热量叫**生长度日(GDD, Growing Degree Days)**:

```
今天攒的热量 = (今天最高温 + 最低温)/2 − 基础温度
```

- "基础温度"是庄稼开始生长的门槛温度(凉季作物约 5℃,暖季作物如玉米约 10℃);低于它就攒 0(太冷不长)。
- 把每天攒的加起来,到某个总额就进入下一个生长阶段(出苗、开花、灌浆)。

**小例子**:玉米基础温 10℃,今天最高 28、最低 12,平均 20 → 攒 20−10 = 10 个热量单位。

### (2) 阳光怎么穿过叶子(Beer–Lambert 定律)
庄稼靠叶子接阳光。但叶子一层挡一层,越往下越暗——就像戴上越来越厚的墨镜,或者站在树荫里。光穿过冠层的衰减公式:

```
透下去的光 = 顶上的光 × e^(−k × LAI)
```

- `LAI`(叶面积指数)= 叶子的"厚度",叶子越多 LAI 越大;
- `k` 是消光系数(叶子越平摊越挡光)。
- 被庄稼**截住**的光的比例 = `1 − e^(−k×LAI)`。叶子越密,截得越多,但有上限(再密也截不到超过 100%)。

### (3) 把光变成干物质(RUE)
截到的光,按一个固定"兑换率"变成生物量。这个兑换率叫**辐射利用效率(RUE, Radiation Use Efficiency)**:

```
今天长的干物质 = RUE × (截到的光比例) × 阳光总量
```

历史上 Monteith(1977)测出大麦等作物大约 **1.4 克/兆焦**(每兆焦太阳能长 1.4 克干物质,约 2.4% 的效率)。

### (4) 缺水就打折(水分胁迫 SWFAC)
跟土壤一样,庄稼缺水就少长。模型算一个 0~1 的折扣 **SWFAC = 实际能吸到的水 ÷ 庄稼想要的水**,乘到生物量增长上。1 = 不缺水,0.5 = 缺水缺到只能长一半。

### (5) 土壤水怎么走:一排"接力水桶"(tipping-bucket)
土壤水最常用的算法特别直观:把土壤分成一层一层,每层是一个**水桶**。下雨灌进最上面的桶,**桶满了(超过"田间持水量")就溢流到下面一桶**,一桶接一桶往下漏。这叫**倾倒水桶法(tipping-bucket)**。它简单、稳定、参数好找,是 DSSAT 和 APSIM 的默认做法。(更高级的有数值解 Richards 方程,更精确但更慢更容易出数值毛病,入门不用碰。)

## 8. 这堆公式怎么变成能点鼠标的"软件"?(厨房比方)

科学家把上面这些公式写成代码后,它还只是一堆程序员才看得懂的文件。要变成 APSIM、DSSAT 那种能点的软件,需要分**三层**封装,正好像一个餐厅:

```
┌─────────────────────────────────────┐
│  第3层 界面/前端(餐厅大堂、菜单)        │  ← 你框选农田、下拉菜单选作物、点"开始"
├─────────────────────────────────────┤
│  第2层 数据接口(采购、备菜)            │  ← 自动对接气象局、卫星、土壤数据库,洗成模型能吃的格式
├─────────────────────────────────────┤
│  第1层 核心引擎(后厨、灶台)            │  ← 所有微分方程和"一步步挪"都在这,追求极致快
└─────────────────────────────────────┘
```

- **第1层 核心引擎**:用 C++ 或 Fortran 写(快),包含所有公式和数值求解。
- **第2层 数据接口**:把天气、土壤、卫星数据自动洗成引擎能读的格式。
- **第3层 界面**:你点的那个壳;你按"开始模拟",其实只是给后厨下了一条指令,后厨算完,前端再画成漂亮的曲线图给你看。

**三个主流模型一句话认识它们**:
- **DSSAT**:Fortran 写的"老字号",所有作物共用一套代码 + 一个土壤模块,靠一堆输入文件(天气、土壤、品种)驱动。
- **APSIM**:模块化"积木",新版用 C# 重写,把模型搭成一棵"组件树",像搭乐高一样组合作物模型。
- **DNDC**:专攻温室气体(尤其 N₂O、CH₄)的 Windows 软件,核心是上面没细讲的"厌氧气球"(算淹水后土壤缺氧、引发反硝化)。

**所有这些软件的引擎,每天都重复同样三件事**(这是最重要的工程套路):
1. **算速率(rate)**:今天各个过程多快(分解、生长、排气)。
2. **积分(integrate)**:用"今天的状态 + 速率 × 一天"算出明天。
3. **更新状态(update)**:把明天的值存好,进入下一天。

记住"**算速率 → 积分 → 更新**"这九个字,你就抓住了所有过程模型软件的心脏。

## 9. 那"你"在这条链里干什么?

看完你会明白自己的位置:
- 你**不需要**去写后厨的 C++ 引擎(那是计算机系的活);
- 你**不需要**去做前端界面(那是软件工程师的活);
- 你的价值在**两端**:
  - **定义机理(灵魂)**:指出某个 f(W)、某个分解公式在你研究的场景下不对,提出更好的农学机制去改它;
  - **解释涌现(灵魂)**:当模型跑出一条奇怪的曲线(比如碳突然骤降),程序员只会以为"代码出 bug 了",而你能看出这是系统越过了某个临界点——这是真实的科学现象。

一句话:**用代码做苦力,用农学做灵魂。**

## 10. 小结 & 下一部分预告

这一部分你应该已经懂了:
1. 模型 = "今天状态 + 规则 → 明天状态",重复无数次;
