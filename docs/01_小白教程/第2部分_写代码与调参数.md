## 1. 热身:把"一个浴缸"写成 6 行代码

先把第一部分最简单的"单个浴缸 + 一阶衰减"写出来,找找感觉:

```python
import numpy as np

C = 100.0          # 浴缸初始水量(碳),100 单位
k = 0.1            # 排水快慢:每天排掉现有量的 10%
history = [C]      # 用一个清单记录每天的水量

for day in range(10):          # 往前挪 10 天
    decay = k * C              # 今天排掉多少 = k × 当前量
    C = C - decay              # 明天的量 = 今天 − 排掉的(这就是"积分/更新")
    history.append(C)          # 记下来

print(np.round(history, 1))
```

**逐行翻译**:
- `C = 100.0`、`k = 0.1`:设好初始水量和水管粗细。
- `for day in range(10):`:重复 10 次,每次代表一天——**这就是第一部分说的"一步步往前挪"**。
- `decay = k * C`:算今天的"出水速度"。
- `C = C - decay`:把今天的量减去排掉的,得到明天的量。
- 运行结果:`[100. 90. 81. 72.9 65.6 59. 53.1 47.8 43. 38.7 34.9]`

看!和第一部分手算的 100 → 90 → 81 → 72.9 **完全一样**。你已经跑出了人生第一个过程模型。

## 2. 正式版:RothC 五个浴缸的完整代码(逐行)

现在升级到第一部分讲的 RothC 五个浴缸。代码长一点,但每块我都拆开讲。

### 2.1 先把"调光器"和常数写成小机器

```python
import numpy as np

def rate_temp(T):
    "温度调光器:冷→接近0,暖→接近1"
    return 47.91 / (1.0 + np.exp(106.06 / (T + 18.27)))

def clay_x(clay):
    "黏粒决定:分解后多少变CO2、多少留在土里"
    return 1.67 * (1.85 + 1.60 * np.exp(-0.0786 * clay))

def iom_falloon(soc):
    "用总碳估算那个'惰性碳'IOM"
    return 0.049 * soc**1.139

K = np.array([10.0, 0.3, 0.66, 0.02])   # 四个缸的排水快慢:DPM, RPM, BIO, HUM(每年)
```

**逐行翻译**:
- `rate_temp(T)`:第一部分那个温度调光器 f(T),这里用的是 RothC 的真实公式 `a = 47.91/(1+e^(106.06/(T+18.27)))`。你不用记这个怪式子,只要知道它干的事就是"冷天给个小折扣、暖天给个接近 1 的折扣"。喂进温度 T,吐出一个折扣。
- `clay_x(clay)`:喂进黏粒含量(%),吐出"变成 CO₂ 的碳 ÷ 留在土里的碳"这个比值。
- `iom_falloon(soc)`:那个永远不动的惰性碳没法测,用总碳 `0.049 × 总碳^1.139` 估。
- `K = np.array([...])`:把四个缸的排水快慢打包成"一排数字"。`np.array` 的好处是后面能一次性对四个缸做运算,不用写四遍。**注意 DPM 的 10 和 HUM 的 0.02 差了 500 倍**(第一部分讲过)。

### 2.2 核心:走一个月

```python
def rothc_step(pools, a, b, c, clay, c_input=(0.0, 0.0), dt=1/12):
    """让 RothC 往前走一个月。pools = [DPM,RPM,BIO,HUM,IOM]"""
    DPM, RPM, BIO, HUM, IOM = pools          # 把5个缸的水量拆出来
    rm = a * b * c                           # 三个调光器(温度a×水分b×覆盖c)乘起来
    active = np.array([DPM, RPM, BIO, HUM])  # 前4个会分解的缸

    # ① 算这个月每个缸"分解掉了多少"
    decayed = active * (1.0 - np.exp(-rm * K * dt))
    total_dec = decayed.sum()                # 四个缸总共分解了多少碳

    # ② 分解掉的碳:一部分变CO2跑掉,剩下流进 BIO 和 HUM
    x = clay_x(clay)
    to_bh  = total_dec / (x + 1.0)           # 流进 BIO+HUM 的部分
    to_co2 = total_dec - to_bh               # 变成 CO2 跑掉的部分
    dBIO = 0.46 * to_bh                      # 其中 46% 进 BIO
    dHUM = 0.54 * to_bh                      # 54% 进 HUM

    # ③ 更新每个缸:先减掉分解的,再加上回流的
    DPM2, RPM2, BIO2, HUM2 = active - decayed
    BIO2 += dBIO
    HUM2 += dHUM

    # ④ 加上这个月外面进来的碳(落叶、秸秆),按 DPM/RPM 分
    DPM2 += c_input[0]
    RPM2 += c_input[1]

    return np.array([DPM2, RPM2, BIO2, HUM2, IOM]), to_co2
```

**逐行翻译**(对照第一部分的"算速率→积分→更新"):
- `rm = a * b * c`:把温度、水分、覆盖三个 0~1 的折扣**乘**起来(第一部分讲过为什么是乘)。
- `decayed = active * (1.0 - np.exp(-rm * K * dt))`:这一行最关键。`np.exp(-rm*K*dt)` 是"这个月底还剩的比例",`1 −` 它就是"被分解掉的比例",再乘当前量 = 分解掉的绝对量。因为用了 `np.array`,**这一行同时算了四个缸**。
- ② 这几行:把分解掉的碳分成"跑掉的 CO₂"和"留下的(46% 进 BIO、54% 进 HUM)"——就是第一部分说的"浴缸之间有水管连着"。
- ③ `active - decayed`:每个缸减掉分解的(出水);`BIO2 += dBIO` 加上回流的(进水)。
- 返回:新的五个缸 + 这个月排了多少 CO₂。

### 2.3 验证你写对了没:复现官方那四个数

## 3. 把"调光器"做成可换的零件库

第一部分说温度调光器有好几种形状(Q10、Arrhenius、三基点)。聪明的做法是把它们做成**可互换的零件**,想换哪个就传哪个:

```python
def f_Q10(T, Tref=20.0, Q10=2.0):
    "最常用:温度每升10度,速率翻Q10倍(常取2)"
    return Q10 ** ((T - Tref) / 10.0)

def f_wfps_bell(wfps, opt=0.6, width=0.25):
    "水分钟形曲线:太干太涝都接近0,中间(0.6)最高"
    return np.exp(-((wfps - opt) / width)**2)

# 演示:把温度调光器作为"零件"传进去,想换就换一个词
def decomp(k, T, wfps, fT=f_Q10):
    return k * fT(T) * f_wfps_bell(wfps)

print(decomp(0.5, 30.0, 0.6))                 # 用 Q10
print(decomp(0.5, 30.0, 0.6, fT=f_Q10))       # 同上,显式指定
```

- `f_Q10`:第一部分提过,"温度每升 10 度速率翻一倍"(Q10=2)。喂温度,吐折扣。
- `f_wfps_bell`:水分的钟形曲线,湿度 `wfps`(充水孔隙度)在 0.6 附近折扣最大。
- `decomp(..., fT=f_Q10)`:注意 `fT` 这个位置可以塞**任何一个温度函数**。想试试别的温度响应(比如"三基点 beta 函数",有最低/最适/最高三个温度的单峰曲线),只要再写一个函数塞进来即可——**这样你就能对比"换个温度公式,结果差多少",这本身就是一个研究点**。

## 4. 作物模型代码(攒积温 + 截光 + 长干物质 + 缺水打折)

把第一部分作物模型的四个动作写出来。这里用一个叫"字典(dict)"的东西打包状态(`state`)和参数(`p`),`state['gdd']` 就是"取出 state 里叫 gdd 的那个值"。

```python
def crop_step(state, wx, p):
    """庄稼往前走一天。wx=今天天气, p=作物参数"""
    # ① 攒今天的积温 GDD(低于基础温就攒0)
    gdd_today = max(0.0, (wx['tmax'] + wx['tmin'])/2 - p['tbase'])
    state['gdd'] += gdd_today

    # ② 叶面积随攒的积温长大(到上限封顶)
    state['lai'] = min(p['laimax'], p['laimax'] * state['gdd'] / p['gdd_mat'])

    # ③ 截到多少光(Beer-Lambert:叶子越密截得越多)
    fint = 1.0 - np.exp(-p['k'] * state['lai'])
    par  = 0.5 * wx['radiation']           # 太阳总辐射约一半是能用的光(PAR)

    # ④ 缺水打折(0~1)
    swfac = min(1.0, state['water_uptake'] / max(wx['pet'] * fint, 1e-9))

    # ⑤ 把光变成干物质(RUE),再乘缺水折扣 → 累加
    dDM = p['rue'] * fint * par * swfac
    state['dm'] += dDM
    return state
```

**逐行翻译**(对照第一部分作物四动作):
- ① `max(0.0, 平均温 − tbase)`:今天攒的热量,低于基础温度 `tbase` 就攒 0(太冷不长)。`+=` 是"累加上去"。
- ② 叶面积 `lai` 随攒够的积温线性长大,`min(...)` 保证不超过上限 `laimax`。
- ③ `1 - np.exp(-k*lai)`:第一部分的"截光比例",叶子越密(lai 越大)截得越多。
- ④ `swfac`:能吸到的水 ÷ 想要的水,封顶到 1。不缺水就是 1,缺水就 < 1。
- ⑤ `dDM = rue * fint * par * swfac`:截到的光 × 兑换率 RUE × 缺水折扣 = 今天长的干物质,累加到 `dm`。

把这个 `crop_step` 放进一个"从播种到成熟"的 `for` 循环里逐日跑,就能画出庄稼生物量的生长曲线。

## 5. 三个"必查"的代码坑(小白版)

代码能跑 ≠ 算得对。三个最常见的坑,每个给你一个"自检"小机器:

### 坑1:碳凭空多了或少了(质量不守恒)
第一部分的铁律是"水不会凭空消失"。写个查账机器:**所有缸的水 + 累计排掉的CO₂ + 流走的,应该永远等于 初始量 + 加进来的**。

```python
def check_mass_balance(pools, cum_co2, cum_leach, init_total, cum_input, tol=1e-9):
    左 = pools.sum() + cum_co2 + cum_leach    # 现在账上所有碳
    右 = init_total + cum_input               # 本应有的碳
    assert abs(左 - 右) < tol, f"碳不守恒!差了 {左-右:.3e}"
```
如果这个报错,说明你某处把碳算重了或漏了。

### 坑2:步子大小会影响结果(步长不收敛)
怎么知道"一天"这个步子够不够小?**把步子减半,看结果变不变**。如果减半后结果明显不同,说明原来步子太大。

```python
def converged(run, dt, atol=1e-3):
    a = run(dt)        # 用步长 dt 跑一遍
    b = run(dt/2)      # 用一半步长再跑一遍
    return np.max(np.abs(a - b)) < atol   # 两次结果几乎一样 → 收敛
```

### 坑3:算出负的碳量
如果步子太大,`C - k*C*dt` 可能变成负数(浴缸里出现负的水,荒谬)。**解决办法不是简单地把负数改成0(那会偷偷破坏守恒),而是用第一部分那个永远为正的"指数衰减"写法 `C * exp(-k*dt)`**。RothC 代码里用的就是 `np.exp(...)`,所以天然不会出负数。

> 还有一条专业经验:解"扩散类"方程(比如土壤热、Richards 水流)时,步子要满足 `Δt ≤ Δz²/(2D)`(D 是扩散快慢,Δz 是土层厚度),否则结果会乱抖发散。这也是第一部分说的"倾倒水桶"更稳的原因——它不解扩散方程,自然没这个坑。

## 6. 第二大块:参数到底怎么"调"出来?

现在回答那个憋了很久的问题:代码里 `k=10`、`RUE=1.4` 这些数,**凭什么是这个值?**

### 6.1 先破除一个迷思
很多人把调参戏称为"炼丹"——瞎试,差不多就行。**这是错的、不严谨的。** 严谨的调参有一套科学流程,而且和你之前关心的"最优化"是一回事。核心思路一句话:

> **拧旋钮,让"模拟出来的结果"尽量贴近"田间实测的结果"。**

把模型想成一台老式收音机,`k`、`RUE` 这些参数就是上面的**旋钮**。调参 = 拧旋钮直到"放出来的歌"(模拟)和"真正的歌"(实测)最接近。

### 6.2 三步走(这是专业流程)

**第一步:先搞清楚哪个旋钮重要(敏感性分析)**
一台收音机几十个旋钮,你不可能每个都仔细拧。先做**敏感性分析(sensitivity analysis)**——找出"拧哪几个旋钮最影响音质"。
- **Morris 法**:每个旋钮随便拧一下,看结果跳多少。很便宜,用来**快速粗筛**,把没用的旋钮先排除。它给两个数:`μ*`(这个旋钮总体多重要)和 `σ`(它和别的旋钮纠缠多深)。
- **Sobol 法**:更精确,把"结果的总波动"**分账**到每个旋钮头上。给 `S_i`(这个旋钮单独贡献多少波动)和 `STi`(它加上和别人的纠缠一共贡献多少)。如果 `STi` 远大于 `S_i`,说明这个旋钮和别人有强烈"联动"。Sobol 准但贵(要跑几千上万次)。
- **策略**:先 Morris 粗筛(几百次)→ 留下最重要的 5~10 个旋钮 → 再 Sobol 精算。

用现成工具 **SALib** 几行就能做:
```python
from SALib.sample import sobol as sobol_sample
from SALib.analyze import sobol as sobol_analyze

problem = {                                  # 描述要分析哪些旋钮、范围多大
    'num_vars': 4,
    'names': ['k_DPM', 'k_RPM', 'k_HUM', 'clay'],
    'bounds': [[8, 12], [0.2, 0.4], [0.01, 0.03], [10, 40]]
}
X  = sobol_sample.sample(problem, 1024)              # 自动生成一大堆旋钮组合
Y  = np.array([run_rothc_to_SOC(x) for x in X])      # 每组都跑一遍模型
Si = sobol_analyze.analyze(problem, Y, print_to_console=True)  # 算出每个旋钮的贡献
```
跑完它会告诉你:哦,`k_DPM` 贡献了 60% 的波动,`clay` 只贡献 5%——那调参就重点拧 `k_DPM`,`clay` 直接用实测值固定。

**第二步:拧旋钮让模拟贴近实测(校准 / calibration)**
怎么衡量"贴得近不近"?用一个**打分**。最直观的是 **RMSE(均方根误差)**——说白了就是"模拟值和实测值平均差多少"(越小越好)。还有两个常用打分:
- **NSE**(纳什效率系数)= `1 − Σ(实测−模拟)² / Σ(实测−平均)²`。满分 1;等于 0 表示"你的模型还不如直接拿平均值预测";小于 0 表示"比平均值还差"。
- **KGE**(Kling-Gupta 效率)= `1 − √[(r−1)² + (β−1)² + (γ−1)²]`,把"相关性 r、是否系统偏高偏低 β、波动幅度对不对 γ"三件事分开打分,比 NSE 更均衡。**小白易踩的坑**:KGE 用平均值预测时不是 0,而是 **1−√2 ≈ −0.41**,所以 KGE 要 > −0.41 才算比平均值强。

**最朴素的校准(小白能完全看懂的版本)**:试一堆 `k` 值,谁让 RMSE 最小就用谁:
```python
def rmse(sim, obs):
    return np.sqrt(np.mean((sim - obs)**2))    # 平均差多少

best_k, best_score = None, 1e9
for k_try in np.arange(8.0, 12.0, 0.1):        # 把 k 从 8 试到 12
    sim = run_model_with_k(k_try)              # 用这个 k 跑模型
    score = rmse(sim, observed)                # 和实测比,打分
    if score < best_score:                     # 谁差得最小就记下谁
        best_k, best_score = k_try, score
print("最佳 k =", best_k, " 误差 =", round(best_score, 3))
```
这就是"网格搜索"。真实研究里旋钮多、跑得慢,会用更聪明的自动工具,但思路一模一样。

**专业工具(知道名字即可)**:
- **PEST / PEST++**:环境模型界最权威的自动校准器,**不用改你的模型代码**——它靠三个文件(告诉它旋钮在哪、怎么读结果、怎么设置)就能套在任何模型外面自动拧。
- **DSSAT 自带 GLUE / GenCalc**:专门调作物品种参数。

**第三步:别只要一个"最佳值",要一个"范围"(贝叶斯 + 不确定性)**
这一步是水平分水岭。前面网格搜索给你一个"最佳 k = 10.2"。但真相往往是:**好几个不同的 k 值,都能让模拟同样贴近实测**——这叫**等效性(equifinality,殊途同归)**。好比好几组不同的旋钮组合,放出来的歌一样好听,你没法说哪组"绝对正确"。

所以更诚实的做法是给一个**概率分布**:"在现有数据下,k 有 95% 的概率落在 9.8~10.6 之间"。这要用**贝叶斯校准 + MCMC 采样**。
- **思路**(贝叶斯公式 `后验 ∝ 似然 × 先验`):把"农学常识"(k 肯定是正数、在某范围内)当**先验**,把"模拟贴合实测的程度"当**似然**,两者结合,得到 k 的**概率分布**(后验)。
- **怎么采样**:用 Metropolis-Hastings(最朴素)、或更高效的 **DREAM、emcee、PyMC** 等工具,让计算机"随机游走"出这条概率曲线。
- **频率派(PEST) vs 贝叶斯(MCMC)的区别**:PEST 给你**一个最佳旋钮位置**;贝叶斯给你**旋钮大概在哪个范围的概率图**。后者在顶刊里更受欢迎,因为它诚实地承认了不确定性。

最小贝叶斯例子(用 emcee,注释看懂思路即可):
```python
import emcee, numpy as np

def log_prior(theta):                 # 先验:旋钮的合理范围(农学常识)
    k, rue, sigma = theta
    if 8 < k < 12 and 1.0 < rue < 4.0 and sigma > 0:
        return 0.0                    # 在合理范围内,允许
    return -np.inf                    # 超出范围,直接否决

def log_like(theta, y_obs):           # 似然:模拟贴合实测的程度
    *params, sigma = theta
    y_sim = run_model(params)
    return -0.5 * np.sum((y_obs - y_sim)**2 / sigma**2 + np.log(2*np.pi*sigma**2))

def log_post(theta, y_obs):           # 后验 = 先验 + 似然(对数下变成加)
    lp = log_prior(theta)
    return lp + log_like(theta, y_obs) if np.isfinite(lp) else -np.inf

sampler = emcee.EnsembleSampler(32, 3, log_post, args=(y_obs,))
sampler.run_mcmc(p0, 5000, progress=True)        # 随机游走5000步
chain = sampler.get_chain(discard=1000, flat=True)
print(np.percentile(chain, [2.5, 50, 97.5], axis=0))   # 输出每个旋钮的"中位数+95%范围"
```
最后那行 `np.percentile(..., [2.5, 50, 97.5])` 就吐出每个参数的"中位数和 95% 可信区间"——这才是一张诚实的答卷。

> **顺带说一句多目标校准**:如果你想同时调准"产量 + N₂O + 土壤水"好几个东西,它们常常冲突(调好产量可能调坏 N₂O)。这时没有唯一最优解,只有一条"权衡曲线"(Pareto 前沿),用 NSGA-II 这类算法求。入门先不碰,知道有这回事即可。
