# 农业生态系统过程模型 · 小白教程
## 第四部分(完结):从一个想法,到一篇能发表、别人能复现的论文

> 这是最后一部分。前三部分你学会了模型怎么算、怎么写代码调参、怎么和 AI 结合、怎么看突变。
> 这一部分把所有东西**串成一条做研究的完整流水线**——从冒出一个念头,到最后发出一篇别人能照着重跑的论文。
> 全程用一个例子串到底:**"改进 DNDC 的水分函数,让它更准地算出极端暴雨后农田的 N₂O 排放。"**

---

## 0. 全景:做研究 = 写一道"能进菜谱书、还能让别人复刻"的菜

把做一项过程模型研究,想象成发明并发表一道菜:

1. **找缺口** —— 发现"还没人把这道菜做好"(科学问题)
2. **备食材** —— 准备干净、可追溯的原料(数据)
3. **下厨** —— 选/改/造一台模型,跑出结果
4. **严格试吃** —— 用没作弊的方式验证它真的好吃(校准与验证)
5. **诚实标注** —— 说清"我有多大把握"(不确定性)
6. **从一口锅到连锁店** —— 把一块地的做法推广到整个区域(升尺度)
7. **发表 + 附完整菜谱** —— 让任何人下载就能复刻你的结果(发表与复现)

下面一步步讲,每步都带上 DNDC 那个例子。

---

## 1. 第1步 找缺口:别人没做好的那道菜

可发表的研究,一定是补了某个**缺口**。过程模型领域的缺口通常是这五类:
- 模型某个**机制算错了或漏了**(结构缺陷);
- 某个机制**从没被检验过**;
- 某个**区域/作物/管理方式还没人建过模**;
- **几个模型谁更准没人比过**(模型互比);
- **没人量过这个模型有多不确定**。

**怎么把一个现象变成模型问题?** 有一条"翻译链"(第一部分提过):
> 田里看到的现象(感知)→ 画出因果框图(概念)→ 写成公式(数学)→ 切成一步步算(数值)→ 变成代码。

还有一个公认的"良好建模"骨架叫 **Jakeman 十步法**(2006):明确目的 → 界定背景 → 概念化 → 选模型族 → 定怎么估参数 → 选评价标准 → 辨识参数 → 验证诊断 → 量化不确定性 → 与替代模型比较。这十步**是反复迭代、试错的**,不是一条直线走完。

**我们的例子**:你在田里发现,一场极端暴雨后,DNDC 算出来的 N₂O 峰值和实测对不上(忽高忽低)。你怀疑是它的**水分调光器 f(W) 在淹水-落干交替时算错了**——这就是一个"结构缺陷"型缺口。

---

## 2. 第2步 选模型:用现成的、改一改、还是从头造?

决策很简单,问三句:
- 现成模型**结构够用,只是参数没调准**?→ 那就只做**校准**(第二部分)。
- 现成模型**某处结构有缺陷**?→ **改造**它。
- 机制**全新,现有模型完全没有**?→ 才**从头造**(很少需要)。

还有一条黄金原则:**"中等复杂度"**。模型不是越复杂越好——**每多加一个过程,就多一堆调不准的参数**。该用奥卡姆剃刀:能少则少,复杂度要配得上你的数据。

**我们的例子**:不从头造,而是在 DNDC 现有的"厌氧气球"框架里**只替换 f(W)**。这是"改造",改动最小、最容易说清楚、参数最容易调准。

---

## 3. 第3步 备食材:数据要干净、可追溯

模型再好,喂垃圾数据也出垃圾。你需要:
- **驱动数据**:逐日天气、土壤剖面、管理记录(播种/施肥/灌溉);
- **校准/验证数据**:实测的 N₂O 通量、产量、土壤碳氮;
- **质量控制(QA/QC)**:补缺失值、剔除异常值。

学术界还要求数据遵循 **FAIR 原则**:可发现(Findable)、可获取(Accessible)、可互操作(Interoperable)、可复用(Reusable)。农学领域有专门的数据标准 **ICASA**(统一变量命名),让不同人的数据能对接。

**我们的例子**:收集华北平原某站点多年的逐日 N₂O 通量(来自通量塔)、气象、土壤数据,按 ICASA 整理好,做好质量控制。

---

## 4. 第4步 校准与验证的铁规矩(最容易被小白做错)

第二部分教了怎么调参(校准)。但**调完不算完,必须验证**。这里有一条铁规矩:

> **不能用同一批数据,又调参又验证。**

打个比方:**这就像考前把答案给学生背,再用同一张卷子考他**——他当然考 100 分,但这**什么也证明不了**。真正的检验,是用**另一张、最好更难的卷子**考他。

正规做法(Klemeš 1986 的分层方案):
- **分样检验(Split-Sample Test, SST)**:把数据分两半,一半调参,**另一半**验证,再互换。
- **差异分样检验(Differential Split-Sample Test, DSST,最严格)**:故意选**气候对比**的时段——**用干旱年的数据调参,用湿润年的数据验证**(或反过来)。这逼着模型在"没见过的气候"下也得准。做气候变化研究**必须**这么验,因为你本来就要预测未来的陌生气候。

**怎么打分才诚实?** 除了第二部分的 RMSE/NSE/KGE,还有一个很有用的"分差工具"叫 **Gauch MSD 三分解**:把"模拟和实测的总误差"拆成三块——
- **整体偏移**(系统性偏高或偏低);
- **斜率不对**(趋势太陡或太平);
- **纯散乱**(剩下的随机散)。

判读法则:如果**偏移或斜率**那块大 → 说明**模型形式不对**(结构问题,得回去改公式);如果只是**散乱**大 → 说明模型**不够精确**(调参问题)。这比只看一个 RMSE 信息量大得多。

**三个词别搞混**:
- **校准(calibration)**:用数据调参数;
- **验证(validation)**:用独立数据检验;
- **评价(evaluation)**:更全面的判断(含诊断、不确定性、和别的模型比)。

**我们的例子**:用湿润年数据贝叶斯校准改进版 f(W) 的参数,用干旱年数据独立验证;报告时同时给 NSE、KGE 和 MSD 三分解,证明改进确实减小了"系统性偏移"。

---

## 5. 第5步 诚实标注"我有多确定"(不确定性)

一个成熟的研究,不会只甩一个数字说"N₂O 是 5.0",而会说"**N₂O 大概在 4~6 之间,有 90% 把握**"——就像天气预报说"70% 概率下雨",而不是拍胸脯说"一定下雨"。

不确定性有四个来源:**输入数据、参数、模型结构本身、观测误差**。最常用的量化办法是**蒙特卡洛**:从参数的概率分布(第二部分贝叶斯得到的)里抽很多组,各跑一遍,得到结果的分布。

还有一招很强:**问一群专家取中位数**。与其信一个模型,不如让很多个模型都跑一遍,取它们的**中位数**——这叫**多模型集合(multi-model ensemble)**。一个里程碑研究(Asseng 等 2013,集合了 **27 个建模组**的小麦模型)发现:充分校准后,**超过一半的模型模拟产量,落在 300 多个田间试验均值的变异系数(±13.5%)以内**,而且**集合中位数往往比任何单个模型都更可靠**。

**我们的例子**:用蒙特卡洛把参数的不确定性传播到 N₂O 预测上,给出 95% 可信区间;并和原版 f(W) 对比,展示改进版的不确定性更小。

---

## 6. 第6步 从一块地推到整个区域(升尺度)

你在**一块地**上证明模型准了。但要回答"整个华北平原排多少 N₂O",得**升尺度(upscaling)**。

这里有个大坑,叫**"支撑变化问题"(change-of-support)**:**在一块地有效的关系,在整个省的尺度上不一定成立**。你不能简单地"把点上的算法套到每个网格格子,再加起来"——这么做会有**聚合误差**。

有多大?真实研究(Hoffmann 等)发现:把数据从 1 公里聚合到 100 公里,平均产量误差在德国某区**小于 15%**、在意大利托斯卡纳**约 20~30%**,个别模型甚至**到 60%**。所以升尺度前一定要**先诊断聚合误差有多大**。

工具上,有 **pSIMS**、**并行网格 DSSAT** 这类"流水线工厂",能把模型在成千上万个网格上批量并行跑,再按行政或环境边界聚合。

**我们的例子**:先在 1 公里和目标分辨率各跑一遍比对,确认聚合误差可接受,再用网格框架把改进版 DNDC 推到整个区域。

---

## 7. 给模型"睁眼看一下":把卫星数据喂进去(数据同化)

模型一旦开跑,就像**蒙着眼凭记忆走路**,走久了会越走越偏。**数据同化(data assimilation, DA)** 就是**让它隔一阵睁眼看一下卫星图、纠正方向**。

- 卫星能定期测到**叶面积(LAI)、土壤湿度**等。DA 在模型运行中,用这些观测**实时校正模型的状态**(比如把模型算的 LAI 往卫星观测拉一拉)。
- 最常用的方法叫**集合卡尔曼滤波(EnKF)**:跑一群略有差异的模型成员,用它们和观测的差异算出"该信模型多少、该信卫星多少",按这个比例融合。
- **DA 和校准的区别(关键)**:校准是**出发前调好罗盘**(调时间不变的**参数**);DA 是**路上不断用 GPS 纠偏**(运行中反复更新时变的**状态**)。两者不是一回事。

真实战绩:把 MODIS 卫星的 LAI 同化进 DSSAT 玉米模型,产量估算评分(R²)从 **0.47 提升到 0.51**;用 Sentinel-1/2 卫星把土壤水和 LAI 一起同化进 WOFOST,能在田块尺度显著改善冬小麦产量估算。

## 8.(选学)把模型连起来:作物 × 水文 × 气候(耦合)

如果你的问题需要多个系统联动(比如气候变化对产量的影响),就要**耦合**不同模型:
- **单向(offline)**:气候模型先算好,把结果"喂"给作物模型(最常见、最简单);
- **双向(online)**:两个模型边跑边互相交换(复杂、昂贵)。

用气候模型(GCM)的结果驱动作物模型前,通常要**降尺度 + 偏差订正**。最简单的是 **delta 方法(变化因子法)**:把气候模型预测的"变化量"叠加到观测基线上——
```
订正后的温度 = 实测温度 + (未来气候模型均温 − 参考期气候模型均温)
```
意思是"只取气候模型预测的**变化趋势**,贴到可靠的历史观测上"。

模型之间怎么对接?有标准接口(如 **BMI**),让不同语言写的模型像插头插插座一样连起来,不用互相改代码。(这部分对入门是"知道有这回事"即可。)

---

## 9. 第7步 发表 + 让别人能复现(最体现现代科研素养)

最后一步,也是越来越被看重的一步:**发表论文,并让任何人都能下载你的东西、重跑出你的结果**。

现代一篇合格的模型论文 = **论文 + 代码仓库 + 归档数据 + 运行环境 + 基准测试**。具体:
- **代码上 Git/GitHub**,做版本管理(像给代码存档、能回退);
- **打一个永久 DOI**(用 Zenodo 之类),让代码的"那个精确版本"被永久引用——**注意:期刊不接受纯 GitHub 链接**,因为它会变、会删,必须是永久归档;
- **用 Docker 容器**把整个"厨房环境"打包(操作系统、依赖库版本全锁住),别人拉下来就能在一模一样的环境里运行;
- **用 Snakemake** 之类把"从原始数据到论文每张图"的全流程写成自动脚本;
- **持续集成(CI)**:每次改代码自动跑测试,防止改坏。

像 **GMD(Geoscientific Model Development)** 这类期刊,**强制要求**:论文必须有"代码与数据可得性"声明,代码和数据须在投稿时就能让审稿人拿到、并永久公开归档,**不允许 embargo(封存)**。

**可复现的终极检验**:**一个陌生人,只凭你的代码仓库 + 容器,能不能重跑出你论文里的主图?** 能,才算真的可复现。

## 11. 给你的现实路线图(0–18 个月)

| 阶段 | 时间 | 干什么 | 过关标准 / 何时改方向 |
|---|---|---|---|
| 找缺口 + 搭骨架 | 0–3 月 | 文献确认缺口属哪类;建 Git 仓库 + 锁环境 | 若发现现成模型结构够用 → 改做校准/同化研究,更快发表 |
| 数据 + 校准验证 | 3–9 月 | 按 ICASA 整理数据;**用 DSST 而非简单 SST**;同时跑频率派和贝叶斯 | 若验证期 NSE<0 或 MSD"斜率/偏移"主导 → 回去改模型结构,别死调参 |
| 不确定性 + 升尺度 | 9–15 月 | 蒙特卡洛传播不确定性;升尺度前先诊断聚合误差 | 若聚合误差 > 年际波动 → 保留更细分辨率 |
| (选)耦合 + 发表 | 15–18 月 | 需要才耦合(用 BMI);投 GMD,配齐代码/数据/容器 | 自检:别人凭你的仓库+容器能重跑出主图吗? |

**会让你改方向的情况**:数据极少 → 转数据同化;多个模型都失败 → 转模型互比(中位数最稳);预算有限 → 用 delta 方法 + 简单耦合;审稿人质疑稳健性 → 补 DSST 干湿年外推。

## ✅ 检查你懂了没（第四部分自测）

1. 为什么"不能用同一批数据又调参又验证"？打个比方。
2. 分样检验（SST）和差异分样检验（DSST）有什么区别？做气候变化研究该用哪个？
3. 升尺度的"支撑变化问题（change-of-support）"是个什么坑？
4. 数据同化（DA）和校准（calibration）本质区别是什么？
5. 一篇"别人能复现"的模型论文，除论文本身还要配齐哪些东西？

<details><summary>点开对答案</summary>

1. 等于考前把答案给学生背、再用同一张卷子考他——必得高分却什么都证明不了。必须用独立、最好更难的数据验证。
2. SST 把数据分两半互相调/验；DSST 故意用气候对比时段交叉（干旱年调、湿润年验）逼模型外推。气候变化研究必须用 DSST。
3. 在一块地标定的关系，聚合到整个区域未必成立，简单"逐格跑再相加"会有聚合误差，升尺度前要先诊断它有多大。
4. 校准调的是时间不变的"参数"（出发前定罗盘）；DA 在运行中用卫星观测反复纠正时变的"状态"（路上用 GPS 纠偏）。
5. 论文 + 代码仓库（Git）+ 永久归档的数据/代码（Zenodo DOI，不能只给 GitHub 链接）+ 运行环境（容器）+ 基准测试。

## 12. 四部分总收尾:你现在站在哪里

恭喜,你已经走完了从"黑箱使用者"到"能看穿、能动手、能做研究"的全程。回看这条链:

```
第一部分:看穿黑箱
  模型=浴缸和水管 → dC/dt=进水−k·C·f(T)·f(W) → 一步步往前挪 → 引擎"算速率→积分→更新"
        │
第二部分:亲手跑起来
  把公式写成 Python(RothC/作物) → 三个代码坑 → 调参三步(筛旋钮→贴实测→给概率范围)
        │
第三部分:扩展与洞察
  AI×模型(老师傅+新徒弟:代理/残差/可微分) → 突变(山谷被填平、湖水变浑、提前预警、真伪三判)
        │
第四部分:做成研究
  找缺口→备数据→改模型→严格校验(别拿同卷子又教又考)→标不确定性→升尺度→可复现发表
```

**最后一句话,也是贯穿全程的那句话**:在这条链里,写代码、跑数值是"苦力",可以学、可以借工具、甚至可以交给 AI 徒弟;而**指出某个机理公式在某种农学情境下不对、并解释模型为什么会涌现出某个反常现象**——这是只有懂农学的你才能做的"灵魂"工作。

**用代码做苦力,用农学做灵魂。** 这四部分给了你做苦力的全套工具,而灵魂,在你自己手里。
