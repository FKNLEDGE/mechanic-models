# 透视黑箱:农业生态系统过程模型(DNDC、CENTURY/RothC、APSIM、DSSAT)的计算内核与软件架构

## TL;DR
- **两大模型家族共享同一计算骨架**:把生态系统拆成"状态变量"(碳氮库、水、生物量),用**一阶动力学/质量守恒 ODE** 描述其变化率,再用**环境修正函数的乘积** f(T)·f(W)·f(底物) 把"潜在速率"缩减为"实际速率",最后几乎全部用**显式欧拉法、固定一日(或亚日)时间步**做数值积分逐日推进——没有解析解,全靠迭代。
- **软件构造上两者都采用"模块化 + 每日 rate→integrate→update"模式**:DSSAT 是 Fortran 编写的 CSM(单一土壤模块 + 可插拔作物模块,六步操作循环);APSIM Classic 是多语言 + "通用建模协议(CMP)"消息引擎,APSIM Next Gen 则完全用 C#/.NET 重写为内存中的**组件树 + [Link]反射依赖注入 + .NET 事件**;DNDC 历史上是 Windows 上的 C++/VB 应用。
- **要自己重写内核**,你只需实现三层:(1) 状态方程(dC/dt=−k·C·f(T)·f(W) 等);(2) 修正函数库(Q10/Arrhenius/β 函数、水分曲线);(3) 一个逐日时间步循环(先算速率、再积分、再更新状态)。本报告给出可直接落地的伪代码与真实参数值。

---

## Key Findings

1. **生物地球化学模型(DNDC/CENTURY/RothC)的核心是多库一阶衰减级联**。土壤有机碳被分成若干概念库(易分解/抗分解/腐殖质/惰性),每个库以 dC/dt = −k·C·f(T)·f(W) 衰减,产物按效率系数在库间流动并释放 CO₂/矿质氮。RothC 用 5 个库(DPM、RPM、BIO、HUM、IOM),据 Coleman & Jenkinson《RothC – A Model for the Turnover of Carbon in Soil》模型描述文档,四个活跃库以一阶衰减分解,年速率常数(year⁻¹)分别为 DPM=10、RPM=0.3、BIO=0.66、HUM=0.02,IOM 惰性不变。CENTURY 用 active/slow/passive 三库:据 NREL/Colorado State University 官方 SOM 子模型文档(Parton et al. 1987),active 库(SOM1C(2))周转时间为"months to a few years depending on the environment and sand content",slow 库(SOM2C)为"20 to 50 years",passive 库(SOM3C)为"400 to 2000 years"。

2. **DNDC 的独特之处是"厌氧气球(anaerobic balloon)"**:它把 **Nernst 方程**(算 Eh)与 **Michaelis–Menten 方程**(算还原反应速率)通过共有的"氧化剂浓度"耦合,动态计算土壤中厌氧微域的体积分数(0=全好氧,1=全厌氧),从而在同一土层中同时模拟硝化(好氧)与反硝化(厌氧)。

3. **作物生长模型(DSSAT/APSIM)的核心是热时间驱动的物候 + 辐射截获 + 生物量积累**。物候用积温 ΣGDD 推进;冠层截光用 Beer–Lambert 定律 I=I₀·exp(−k·LAI);生物量用辐射利用效率 RUE(Monteith 方法)即 ΔDM=RUE·(1−e^(−k·LAI))·PAR,再用水分胁迫因子 SWFAC、氮胁迫因子 NFAC 等下调。

4. **土壤水有两条技术路线**:DSSAT 与 APSIM-SOILWAT 用**"倾倒水桶(tipping bucket)"级联层模型**(超过田间持水量 DUL 的水按比例 SWCON 下渗),概念简单、数值稳定;APSIM-SWIM 与少数 DSSAT 变体用**数值解 Richards 方程**的有限差分法,物理上更严谨但更慢、更易数值不稳。

5. **数值方法上,几乎所有这些模型都用显式(前向)欧拉法、固定一日时间步**。这是设计选择:与日尺度天气驱动数据匹配、实现简单、对一阶衰减类方程足够稳定。土壤剖面在空间上离散为分层(layered),层间通量(热、水)用有限差分近似。

6. **软件架构的统一范式是"模块沿学科分界 + 每日六步/rate-integrate-update"**。DSSAT-CSM 每个模块都执行:run初始化→season初始化→速率计算→积分→日输出→汇总输出,主程序控制何时调用哪一步,模块间只通过少量"接口变量"通信,可即插即拔。

## Details

### 第一部分(A):数学/计算内核——"它们如何计算"

#### A.1 控制状态方程:一阶衰减级联与质量守恒

**生物地球化学模型的通用骨架。** 所有这类模型(DNDC、CENTURY、RothC、APSIM-SoilN、DSSAT-CENTURY)都把土壤有机质视为若干**概念碳库(conceptual pools)**,假设每个库的分解服从**一阶动力学**:

  dCᵢ/dt = −kᵢ · Cᵢ · f(T) · f(W) · (其他修正)

其中 Cᵢ 是第 i 库的碳量,kᵢ 是该库的"特征(最大/潜在)分解速率常数"。一阶动力学意味着孤立衰减是指数衰减 C(t)=C₀·e^(−kt);"周转时间"约为 1/k。关键在于:**各库不是孤立的**,一个库分解的产物按固定**效率系数/转移系数**流入其他库(微生物量、腐殖质)并把一部分作为 CO₂ 释放——这构成"级联(cascade)"。

**RothC(Rothamsted Carbon Model)** 是最干净的范例,适合作为你重写的第一个练手对象:
- 5 个库:DPM(易分解植物物料)、RPM(抗分解植物物料)、BIO(微生物量)、HUM(腐殖化有机质)、IOM(惰性有机质)。
- 4 个活跃库的年分解速率常数:k_DPM=10、k_RPM=0.3、k_BIO=0.66、k_HUM=0.02 yr⁻¹;IOM 不分解(Coleman & Jenkinson 模型描述文档)。
- 月时间步。Rothamsted 官方文档给出的真实计算示例(逐字):某月若修正后有效时间为 0.3561/12,则 "DPM becomes 0.1533 * exp[- 10 * 0.3561 / 12] = 0.1140;RPM becomes 4.4852 * exp[- 0.3 * 0.3561 / 12] = 4.4455;BIO becomes 0.6671 * exp[- 0.66 * 0.3561 / 12] = 0.6542;HUM becomes 25.8576 * exp[- 0.02 * 0.3561 / 12] = 25.8423"。用这组数字做你的单元测试基准。
- DPM、RPM 都分解为 CO₂ + BIO + HUM;去向 CO₂ 与去向 (BIO+HUM) 的比例由土壤黏粒含量决定;(BIO+HUM) 再按 46% BIO、54% HUM 分配。
- 初始库可用稳态(spin-up)或用 pedotransfer 函数估计;IOM 常用 Falloon et al. (1998)(Soil Biology & Biochemistry 30(8):1207–1211,"Estimating the size of the inert organic matter pool from total soil organic carbon content for use in the Rothamsted carbon model")的公式 IOM=0.049·SOC^1.139 估计——该库不随时间变化,故必须独立初始化。

**CENTURY** 增加了基于凋落物化学的进入分配:植物残体先按木质素/氮比分到结构库(structural)与代谢库(metabolic),再进入 active/slow/passive 三个 SOM 库。结构库分解速率受其木质素含量抑制;据 NREL/Colorado State 官方文档,"土壤质地影响 active 库的周转速率(砂质土更快)以及 active 稳定化为 slow 库的效率(黏质土稳定化率更高)"(原文:"The soil texture influences the turnover rate of the active soil SOM (higher rates for sandy soils) and the efficiency of stabilizing active SOM into slow SOM (higher stabilization rates for clay soils)")。三库 C:N 比随矿质氮水平线性变化(随表层矿质 N 从 0 升到 2 g N/m²:active 15→3、slow 20→12、passive 10→7)。

**APSIM-SoilN** 继承 CERES-N:SOM 分为 BIOM(微生物量)、HUM(腐殖质)、可选 INERT(惰性);新鲜有机质 FOM 分为三个亚库——FPOOL1 类碳水化合物(默认 0.2)、FPOOL2 类纤维素(0.7)、FPOOL3 类木质素(0.1)。每个库(除惰性)按一阶过程分解,速率常数被土温、土壤水分、C:N 因子修正。矿化/固持由分解释氮与微生物合成需氮的平衡决定;若矿质氮不足以满足固持需求,分解速率被下调。

**DNDC 的分解方程(来自官方 Scientific Basis 文档,Eq. 3):**

  dC/dt = CNR · μ · (S·kₗ + (1−S)·kᵣ) · [C]

其中 [C] 为有机碳含量(kg C/ha),S 为该库中易分解组分的比例,(1−S) 为抗分解组分比例,kₗ、kᵣ 分别为易/抗分解组分的特征分解速率(SDR,1/day),μ 为温度×水分因子,CNR 为 C/N 比还原因子。DNDC 给出的真实 SDR 值:很易分解凋落物、易分解凋落物、抗分解凋落物、易分解微生物、抗分解微生物、易分解腐殖质(humads)、抗分解腐殖质分别为 0.074、0.074、0.02、0.33、0.04、0.16、0.006 (1/day)。

#### A.2 DNDC 的氧化还原核心:Nernst + Michaelis–Menten + 厌氧气球

这是 DNDC 区别于其他模型的"灵魂"。降雨/灌溉/淹水后,土壤从非饱和转为饱和,O₂ 被消耗,一系列还原反应(NO₃⁻、Mn⁴⁺、Fe³⁺、SO₄²⁻ 的还原以及产甲烷)依吉布斯自由能高低**顺序**发生。

**Nernst 方程(Eq. 1)** 算土壤体相 Eh:

  Eh = E₀ + (RT/nF)·ln([氧化态]/[还原态])

其中 R=8.314 J/mol/K,T=273+t(°C) 为绝对温度,n 为转移电子数,F=96485 C/mol 为法拉第常数。

**双底物 Michaelis–Menten 方程(Eq. 2)** 算氧化剂被还原的速率:

  F[oxidant] = a·[DOC/(b+DOC)]·[oxidant/(c+oxidant)]

a、b、c 为系数,DOC 为溶解性有机碳浓度。

**厌氧气球**:因为两方程共有"氧化剂浓度"这一因子,DNDC 用它把二者耦合,定义土壤的**厌氧体积分数**。Nernst 算出体相 Eh→据此把土壤分成厌氧微域(气球内)与好氧微域(气球外)→底物(DOC、NO₃⁻、NH₄⁺)按比例分配到两类微域→气球内走还原反应(反硝化、产甲烷),气球外走氧化反应(硝化、甲烷氧化)→反应速率都用 M–M 方程。气球随氧化/还原反应动态"膨胀/收缩":淹水后 O₂ 耗尽气球膨胀至最大并"爆破",此时 NO₃⁻ 成为新的主导氧化剂,新气球诞生并随 NO₃⁻ 耗竭而膨胀……如此追踪 O₂→NO₃⁻→Mn⁴⁺→Fe³⁺→SO₄²⁻→CO₂ 的逐级还原,得到 Eh 动态与 N₂O/CH₄ 的产生消耗。

**硝化(DNDC Table 2,真实方程):**
- 硝化菌相对生长率:dG/dt = 0.0166·DOC/(1+DOC) + Fm/(1+Fm)
- 硝化菌相对死亡率:dD/dt = 0.008·BIO·(1+Fm)/(1+DOC)
- 生物量净增:dBIO/dt = (dG/dt − dD/dt)·BIO·Fₜ·Fₘ
- 硝化速率:Rn = 0.005·[NH₄⁺]·BIO·pH (kg N/ha/day)
- 温度因子:Fₜ = 3.503^((60−T)/(60−34.22))·e^(3.503·(T−34.22)/(60−34.22))
- 水分因子:Fm = 0.8 + 0.21·(1−wfps),若 wfps>0.05;否则 Fm=0
- 硝化诱导 NO:NO = 0.0025·Rn·Fₜ;硝化诱导 N₂O:N₂O = 0.0024·Rn

**反硝化(DNDC Table 3,真实方程):** 当 Eh 降到约 500 mV 或更低时启动,反硝化菌在厌氧微域内生长:
- NOₓ 反硝化菌相对生长率:GR_NOx = Fₜ·GR_max·[C/(K_C+C)]·[NOₓ/(kₙ+NOₓ)]
- 总反硝化菌生长率:GR = Fₜ·(GR_NO3·PH1 + GR_NO2·PH2 + GR_NO·PH3 + GR_N2O·PH4),其中温度因子 Fₜ = a·2^((T−22.5)/10)(注意这是 **Q10=2** 形式),pH 因子 PHx = a·(pH−b)
- 生长率项 (dBIO/dt)_g = GR·BIO(t);死亡率项 (dBIO/dt)_d = Mc·Yc·BIO(t)
- 碳消耗率:dC/dt = (GR/Yc + Mc)·BIO(t)
- N 氧化物消耗率:dNOx = (GR_NOx/Y_NOx + M_NOx·NOx/N)·BIO(t)

#### A.3 DNDC 的土壤物理:热传导与水流的有限差分

DNDC 的土壤气候子模型把剖面分层,逐层解热与水的一维通量方程(来自 DNDC 方程附录):
- 层间热通量:q_{i,i−1} = −k_{i,i−1}·(Tᵢ−T_{i−1})/(zᵢ−z_{i−1})(傅里叶热传导定律的差分形式)
- 能量守恒(更新层温):dTᵢ = dt·(q_{i,i−1} − q_{i+1,i})/(Cᵢ·lᵢ),其中 Cᵢ 为层体积热容
- 层间水流:Q_{i,i−1} = −K_{i,i−1}·(hᵢ−h_{i−1})/(zᵢ−z_{i−1}),h 为水势水头(达西定律差分形式)
- 水分守恒:dθᵢ = dt·(θ通量_{i,i−1} − θ通量_{i+1,i})/(n·lᵢ)
- 相对导水率:K/K_sat = θ^(2β+3)(Campbell/Clapp-Hornberger 形式)
- 潜在蒸散用 Thornthwaite 型公式(E₀ 由热量指数 I 与月均温推算)

这些都是经典的**分层有限差分**:把连续的偏微分方程(热传导方程、Richards 方程)在空间上离散成层、在时间上离散成日步,然后逐层、逐日更新。

#### A.4 作物模型的核心方程

**物候/热时间(thermal time, GDD)。** 发育速率由积温驱动而非日历天数。每日热时间:

  GDD_day = max( (T_max+T_min)/2 − T_base, 0 )

累积 ΣGDD 到某阈值即进入下一物候阶段。常用 T_base:冷季作物约 5°C,暖季作物(玉米、高粱、水稻、大豆)约 10°C;通常还设上限 T_cap(如 30°C),超过则不再增加或封顶。CERES、APSIM 用更精细的分段/曲线型温度响应(如三基点:T_base、T_opt、T_max),而非简单线性。

**辐射截获:Beer–Lambert 定律。** 冠层对光的衰减类比朗伯-比尔定律:

  I = I₀·exp(−k·LAI)

I₀ 为冠层顶入射辐射,k 为消光系数(取决于叶角分布,叶片越水平 k 越大),LAI 为叶面积指数。被截获的比例为 (1−exp(−k·LAI))。

**生物量积累:两条路线。**
- **RUE(辐射利用效率)路线**(DSSAT-CERES、APSIM、EPIC 默认):ΔDM = RUE·(1−exp(−k·LAI))·PAR。RUE(g/MJ)是 Monteith(1977)发现的"干物质 vs 截获辐射"近似线性关系的斜率。其经典论文 Monteith, J.L. (1977)《Climate and the Efficiency of Crop Production in Britain》(Phil. Trans. R. Soc. B 281:277–294)原文写道:"Total production of dry matter by barley, potatoes, sugar beet, and apples is strongly correlated with intercepted radiation and these crops form carbohydrate at about 1.4 g per MJ solar energy, equivalent to 2.4% efficiency."——即 C3 作物约 1.4 g/MJ(对太阳总辐射)。这是最广泛使用的方法,因其形式简单。
- **光合驱动路线**(CROPGRO、机理光合模型):用 Farquhar 型叶片生化光合模型 + 冠层辐射传输,逐层逐时积分总光合(GPP),再减去呼吸得净同化。更机理但参数更多、更慢。

**生物量分配。** 净同化的碳按物候阶段分配到叶、茎、根、穗/籽粒。CERES 用"库-源(sink-source)"概念决定各器官分配比例,水分/养分胁迫时修正。CERES 的产量=单位面积粒数×平均粒重,粒数由临界期(开花前后)的生物量增长率决定。

**叶面积发育。** 由叶片起始率、出叶率(phyllochron,常以热时间计)、单叶扩展与温度的关系驱动;胁迫(水、氮)与衰老使 LAI 下降。

**水分平衡:倾倒水桶。** DSSAT 与 APSIM-SOILWAT 用一维"级联水桶"(Ritchie 1998):每层用下限 LL(凋萎点)、田间持水量 DUL(drained upper limit)、饱和含水量 SAT 定义。当某层含水量超过 DUL,超出部分的一个比例 SWCON(每层可设)在一天内排到下一层;低于 DUL 时有非饱和扩散流。径流用 USDA 曲线数法;蒸发用 Priestley–Taylor 或 Penman–Monteith 算潜在值再按覆盖度修正。**优点是数值稳定、参数易得**;缺点是物理上简化(Kröbel 等指出 DNDC 这类倾倒水桶不适合精确模拟土壤水)。APSIM-SWIM2/SWIM3 与个别 DSSAT 变体改用数值解 **Richards 方程**(基于达西-白金汉势梯度),更精确但更慢。

**水分与氮胁迫因子。** DSSAT 把潜在蒸散 ETo 按 LAI 与能量消光系数 Kep 分给冠层潜在蒸腾 Ep 与土面潜在蒸发 Es。逐层潜在根系吸水(取决于根长密度与各层可利用水比例)累加;若总潜在吸水 < Ep,蒸腾被下调。**水分胁迫因子 SWFAC = 实际蒸腾(根系吸水)/潜在 Ep**,用于下调日光合同化;**膨压因子 TURFAC**(稍早于 SWFAC 触发)下调叶、茎、穗的扩展生长。SWFAC、TURFAC 取值 0–1,1 表示无胁迫。氮胁迫(NFAC)类似下调光合与生长。

#### A.5 环境修正函数:把潜在速率缩减为实际速率

这是所有过程模型的统一哲学——**乘法式限制因子框架(multiplicative limiting-factor framework)**:

  实际速率 = 潜在速率 · f(T) · f(W) · f(底物) · f(pH) · …

每个 f 都归一化到 [0,1]（或温度因子可略大于 1）。常见函数形式:

- **温度响应:**
  - **Q10 形式**:rate(T) = rate_ref·Q10^((T−T_ref)/10),Q10 是温度每升 10°C 速率的倍数,SOM 分解常用 Q10≈2(也有用 1.4)。DNDC 反硝化温度因子 Fₜ=a·2^((T−22.5)/10) 就是 Q10=2 的实例。
  - **Arrhenius 形式**:rate ∝ exp(−Ea/(R·T)),Ea 为活化能。Q10 实际上是 Arrhenius 的近似。
  - **β 函数/三基点(cardinal)函数**:用 T_min、T_opt、T_max 构造单峰曲线(如 CERES、APSIM 的物候温度响应),超过 T_opt 后速率下降——这是 Q10/Arrhenius(单调上升)无法表达的,更符合生物学。CENTURY 月版用指数函数、日版用反正切函数(arctangent,在 30°C 归一化)。
- **水分响应:** 通常是关于充水孔隙度(WFPS)或相对含水量的钟形/分段曲线——太干微生物活性受限、太湿则缺氧。DNDC 硝化水分因子 Fm=0.8+0.21·(1−wfps) 即一例。
- **底物响应:** 一阶(正比于底物浓度)或 Michaelis–Menten 饱和型 [S/(K+S)]。

**重要概念:潜在 vs 实际。** 模型几乎都先算"潜在"过程(无胁迫下的最大速率/最大生长),再用一串 [0,1] 的修正因子下调到"实际"。这与软件中"先算需求(demand)、再算供给(supply)、再仲裁(arbitration)"的结构一一对应(见 APSIM 的 Arbitrator)。

#### A.6 数值方法:ODE 在计算机上究竟怎么解

这些耦合非线性 ODE **没有解析解**,必须数值积分。要点如下:

**显式(前向)欧拉法 + 固定一日时间步是绝对主流。** 状态更新的通式:

  C(t+Δt) = C(t) + Δt · (dC/dt)|_t

即"用当前时刻的速率乘以时间步长,加到当前状态上"。Wageningen 的 FSE(Fortran Simulation Environment)、其 Python 后裔 PCSE、CropSyst、DSSAT、APSIM 全部默认用**固定一日步的欧拉积分**。PCSE 文档明确:"engine 用与 FSE 相同的方法:固定一日时间步的欧拉积分。"CropSyst 文档:"积分用欧拉法,日时间步。"

**为什么用最简单的欧拉法?**(1) 驱动数据(天气)本来就是日尺度;(2) 实现简单、易调试、易让领域科学家理解;(3) 对一阶衰减这类"温和"方程,日步通常稳定。代价是精度只有一阶(局部误差 O(Δt²)),且对"刚性(stiff)"或快变过程可能不稳定。

**亚日(sub-daily)步与算子分裂。** 当某过程快变(如降雨后的反硝化、土壤热扩散),模型会对该子过程用更小的步长。DNDC 对厌氧气球/反硝化用**小时步**(注意上文 dBIO/dt 等速率单位是 1/h,BIO=∫24·dBIO/dt 即把小时步累加成日)。这本质是**算子分裂(operator splitting)**:把"分解""硝化""反硝化""产甲烷"等过程在一个时间步内**按顺序依次求解**(而非联立),每个子过程可用各自合适的步长。算子分裂的解是一阶时间精度,只要各子算子至少一阶精度即可;算子施加的先后顺序对一阶精度不敏感。

**空间离散。** 土壤剖面离散为层(典型:表层 100–150 mm,底层 300–500 mm,共约 10 层)。层间热/水通量用**有限差分**近似(如 A.3 中 DNDC 的 q、Q 表达式),这等价于把热传导方程、Richards 方程在空间上半离散、在时间上用欧拉法推进。

**数值稳定性与步长选择。** 显式欧拉对扩散型方程有稳定性限制(冯·诺依曼条件,Δt 受 Δz² 约束);若层很薄或导水/导热率很高,日步可能违反稳定条件而振荡——这正是倾倒水桶(不解微分方程,只做"超出即下泄"的代数操作)比数值解 Richards 方程**更稳健**的原因。隐式(后向)欧拉无条件稳定但需解(可能非线性的)方程组,这些模型一般回避之,改用倾倒水桶或小步长显式法。

**初始化与 spin-up。** 慢周转碳库(CENTURY 的 passive、RothC 的 HUM/IOM)周转时间达数百到数千年,实测难以分库。标准做法是**spin-up(预热运行)**:用代表性气候与管理把模型跑很多年(常数百至上万年)直到慢库达到近似稳态/平衡,再以此作为正式模拟的初始条件。RothC 可直接用"逆模式"由已知总 SOC 反推各库,或从 IOM 之外全置零起跑让模型自行收敛到稳态。

**驱动/边界数据。** 主要是**逐日天气**(最高/最低温、降水、太阳辐射,有时风速、湿度),加上土壤理化属性、管理事件(播种、施肥、灌溉、耕作、收获)。模型逐日读入这些"强迫(forcing)"数据驱动状态演化。

#### A.7 两段可直接落地的伪代码

**(1) 多库 SOC 分解(RothC/CENTURY 风格,显式欧拉,日步):**
```
# 状态: pools[i] = 各碳库碳量; k[i] = 各库速率常数(1/day)
# transfer[i][j] = 库 i 分解产物流向库 j 的比例; resp_frac[i] = 库 i 呼吸为CO2的比例
for day in range(n_days):
    T, theta = weather[day].temp, soil_moisture[day]
    fT = Q10 ** ((T - T_ref) / 10.0)        # 温度修正
    fW = moisture_response(theta)            # 水分修正 (0..1)
    rate_mod = fT * fW
    dC = [0.0]*n_pools
    CO2 = 0.0
    for i in range(n_pools):
        decomp_i = k[i] * pools[i] * rate_mod   # 该库本步分解量
        dC[i] -= decomp_i
        CO2    += decomp_i * resp_frac[i]
        for j in range(n_pools):                # 产物级联到其他库
            dC[j] += decomp_i * (1 - resp_frac[i]) * transfer[i][j]
    # 加入外部输入(残体/有机肥)
    for i in range(n_pools):
        dC[i] += input_flux[day][i]
    # 更新状态(欧拉积分, Δt=1 day)
    for i in range(n_pools):
        pools[i] += dC[i]
    record(day, pools, CO2)
```

**(2) 作物生物量积累(RUE + Beer 定律 + 热时间物候 + 水分胁迫,日步):**
```
TT_cum = 0.0; LAI = LAI_init; biomass = 0.0; stage = 0
for day in range(planting, maturity_max):
    Tavg = (weather[day].tmax + weather[day].tmin) / 2.0
    dTT  = max(min(Tavg, T_cap) - T_base, 0.0)   # 当日热时间
    TT_cum += dTT
    if TT_cum >= stage_threshold[stage]:          # 物候推进
        stage += 1
    # 冠层截光 (Beer-Lambert)
    fIPAR = 1.0 - exp(-k_ext * LAI)
    PAR   = 0.5 * weather[day].radiation          # 总辐射的约一半为PAR
    # 胁迫因子
    SWFAC = water_uptake(day) / max(potential_Ep(day), 1e-9)
    SWFAC = clamp(SWFAC, 0, 1)
    NFAC  = nitrogen_stress(day)                  # 0..1
    # 潜在 → 实际 生物量增量 (RUE 路线)
    dBio_pot = RUE * fIPAR * PAR
    dBio     = dBio_pot * min(SWFAC, NFAC) * temp_factor(Tavg)
    biomass += dBio                                # 欧拉积分
    # 按物候阶段分配到器官 & 更新 LAI
    partition(dBio, stage)                         # 叶/茎/根/籽粒
    LAI += d_leaf_area(dBio, stage, TURFAC)
    LAI -= senescence(stage, TT_cum)
    if stage == MATURITY: break
    record(day, biomass, LAI, stage)
```

### 第二部分(B):参数与模型结构(简述)

**速率常数如何进入方程。** 上文每个 k、RUE、SDR、Q10、消光系数 k_ext、SWCON、DUL/LL/SAT 都是"参数"。它们分两类:
- **可测/显式参数(measured/explicit)**:有明确物理意义、可直接测量,如土壤分层的 DUL、LL、SAT、容重、黏粒含量、初始 SOC。
- **拟合/过程参数(fitted/process)**:无法直接测、需通过校准拟合,如品种系数(物候热时间阈值、最大粒数、潜在粒重)、各概念碳库的分配比例与速率常数。

**参数如何嵌入代码——这是"研究代码变产品"的关键设计:把参数外置于源码之外。**
- **DSSAT**:参数放在**外部文件生态**里——实验文件 FileX(*.SNX/*.MZX 等,树状结构,含 CU 品种、FL 田块、IC 初始条件、MP 播种、MI 灌溉、MF 施肥、MR 残体、SM 模拟控制等小节)、天气文件 *.WTH(FILEW)、土壤文件 *.SOL(FILES)、品种系数文件 *.CUL、生态型文件 *.ECO、物种文件(species file,CROPGRO 的"Crop Template"法)。品种系数文件让你"改文件不改代码"即可换品种。
- **APSIM**:参数外置于作物参数文件(crop parameter file,分"作物常数"与"品种参数"两部分,可通过开关切换不同过程算法);Classic 用 XML,Next Gen 用 .apsimx(JSON)。
- **DNDC**:通过 GUI 输入,内部参数(如 62 种植物的默认特性)存于参数表,可被用户修改。

把参数与代码分离,使得**重新参数化一个新作物只需极少甚至零源码改动**,极大加速测试与验证——这是 DSSAT/APSIM 模块化设计的核心收益之一。

### 第三部分(C):软件架构——"它们如何被构建"

#### C.1 DSSAT-CSM:Fortran 模块化 + 六步操作循环

- **语言与核心**:Fortran(开源,见 GitHub `DSSAT/dssat-csm-os`)。DSSAT v3.5 之前每个作物模型各自带土壤模块,导致维护困难、轮作易出 bug。2003 年(Jones 等)重设计为 **CSM(Cropping System Model)**:**所有作物共用一套代码、一个土壤模块**。
- **模块化设计哲学**:模块沿**学科分界**(天气、土壤、植物、SPAM 土-植-气界面、管理);每个模块至少是一个 Fortran 子程序(或一组),模块间**只通过明确定义的接口变量**作为子程序参数传入传出通信;可"即插即拔"替换或新增模块而不影响主程序与其他模块;支持不同语言编写的模块互联。
- **结构层级**:主驱动程序(DSSAT-CSM,控制时间循环、按用户开关决定调用哪些模块、控制打印时机)→ Land Unit 模块(单一land unit 上所有组件的汇聚点,也是应用驱动与模块间的唯一接口)→ Primary 模块(Weather、Soil、Plant、SPAM、Management)→ Sub 模块(Soil 下有 soil dynamics、soil temperature、soil water[倾倒水桶]、soil N&C;CROPGRO 模板;CERES-Maize/Wheat/Rice、SubSTOR-Potato 等独立作物模块)。Sub 模块的行为与 Primary 模块完全一样,可多层嵌套。
- **每个模块的六步操作循环(关键!这是"rate-integrate-update"模式在 DSSAT 的体现)**:① run 初始化 ② season 初始化 ③ **速率计算(rate calculations)** ④ **积分(integration)** ⑤ 日输出 ⑥ 汇总输出。主程序控制每一步何时激活。**状态变量在积分后写出**(代表当日结束时的系统状态)。这使每个模块能独立读输入、自初始化、算速率、积分自己的状态变量、写输出(此设计改编自 van Kraalingen 1991, 1995 的 FSE/FST 工作)。
- **两种加新作物的方式**:(1) 写一个新作物模块,按 Plant 模块接口接入(CERES、马铃薯、甘蔗、向日葵走这条路);(2) 用 **Crop Template** 法(CROPGRO 方式),只改物种模板文件不改代码(faba bean、tomato、chickpea 等)。
- **四种运行模式**:命令行参数指定——基础模式(交互式敏感性分析、模拟 vs 实测对比)、多年同一土壤初值模式、轮作模式(土壤只在最开始初始化一次,持续运行)、空间模式(精准农业/土地利用)。
- **文件生态**:FileX(实验)、*.WTH(天气)、*.SOL(土壤)、*.CUL/*.ECO(品种/生态型)、输出 OUTG/OUTN/OUTS 等。遗留的 COMMON block 共享数据被视为不良实践,新版用 `csm_io` Fortran module + 内存数据结构替代;并行网格版用 MPI + NetCDF(`dssat_mpi`、`dssat_netcdf` 模块,父进程派生多个子 CSM 实例)。

#### C.2 APSIM Classic:多语言 + 通用建模协议(CMP)消息引擎

- **语言**:多语言(官方称"6 种编程语言""数十万行代码"),核心科学模块多为 Fortran(如 `SoilN.f90`,见 GitHub `APSIMInitiative/APSIMClassic`)。
- **架构隐喻是"轮毂与辐条(hub and spokes)"**(spider diagram):中央是**仿真引擎(simulation engine)**,驱动仿真过程、控制所有独立模块间的**消息传递**;周围是各生物物理模块(作物、土壤水[SOILWAT 倾倒水桶 / SWIM Richards]、SoilN、SoilP、土壤 pH、侵蚀、残体)、管理模块、I/O 模块。
- **通用建模协议(Common Modelling Protocol, CMP)**:模块间通过引擎传递变量/事件消息,而非直接函数调用。模块可"插入(plug in)"。CMP 也支撑 FarmWi$e 等其他决策工具。
- **过程库(process library)**:所有作物用**相同的生理学原理**(物候、生物量、冠层、根系、衰老、水、氮、磷),差异只在阈值与响应函数形状;这些被编进一个独立模块的子程序块,各作物调用。可在子模块内/间切换不同算法(开关),便于比较建模方法。常数与品种参数外置于作物参数文件。

#### C.3 APSIM Next Generation(APSIM-X):C#/.NET 完全重写

(以下来自 Holzworth 等 2018 论文《APSIM Next Generation: Overcoming challenges in modernising a farming systems model》Environ. Model. Softw. 103:43–51、APSIM NextGen 官方文档与 `APSIMInitiative/ApsimX` 仓库)

- **背景与选型**:2014 年起从零重写。C# 为编程语言,配合 MONO 与 GTK# 实现 Windows/Linux/macOS 跨平台运行。输出写入 SQLite 数据库(取代 Classic 的文本输出)。
- **模型即内存中的"组件树"**:所有模型都是普通 .NET 类,**必须派生自基类 `Model`**。`Model` 提供树结构三属性:`Name`、`Parent`、`Children`(`List<Model>`)。规范的树根:`Simulations` → `Simulation` → `Zone` → 各子模型(土壤、作物、时钟、管理、报告)。
- **.apsimx 文件是这棵树的 JSON 序列化**:每个节点带 `$type` 类型判别符(如 `"Models.Core.Simulation, Models"`、`"Models.Manager, Models"`、`"Models.Soils.Nutrients.Nutrient, Models"`),子节点嵌在 `"Children": [...]` 数组里。模型必须可二进制与 JSON 序列化;只有 public 属性被序列化(禁止 public 字段)。每个模型需 `[Serializable]` 特性。
- **依赖注入:`[Link]` 特性 + 运行时反射**:模型要与其他模型通信,就声明一个带 `[Link]` 的字段,如 `[Link] private Clock clock = null;`;APSIM 在仿真开始时用反射按类型(并可按名)在作用域内查找匹配模型并赋值。`LinkType` 变体:`LinkType.Child`(子模型,可 ByName)、`LinkType.Ancestor`(祖先模型)、`LinkType.Path`(按路径如 `[Phenology].DltTT`)。作用域解析算法:递归查所有子代、兄弟、再递归查父辈的兄弟。推荐 `[Link]` 指向**接口**(`IClock`、`ICrop`、`ISummary`)以实现松耦合、可替换实现。
- **事件/消息系统:.NET 事件 + `[EventSubscribe]`**:模型用普通 .NET 语法声明事件 `public event EventHandler MyNewEvent;` 并 `Invoke`;其他模型用方法上的 `[EventSubscribe("事件名")]` 特性订阅,框架自动连接、自动断开。**`Clock` 模型是中央事件发布者**,逐日按固定顺序发布事件。多个模型订阅同一事件时,**按它们在 Explorer 树中出现的顺序处理**。
- **每日仿真编排顺序(来自 APSIM NextGen 自动生成的 Clock 文档,体现"潜在→仲裁→实际→更新"模式)**:`DoWeather` → `DoDailyInitialisation` → `StartOfDay` → `DoManagement`(日初管理,先于生物物理计算)→ `DoPestDiseaseDamage` → `DoEnergyArbitration` → `DoSoilWaterMovement` → `DoSoilTemperature` → `DoSoilOrganicMatter` → `DoSurfaceOrganicMatterDecomposition` → `DoUpdateWaterDemand` → `DoWaterArbitration` → `PrePhenology` → `DoPhenology` → `DoPotentialPlantGrowth`(算潜在生长)→ `DoPotentialPlantPartioning`(算潜在分配)→ `DoNutrientArbitration`(养分仲裁约束供给)→ `DoActualPlantPartioning`(实际分配)→ `DoActualPlantGrowth`(实际生长积分)→ `DoStock` → `DoLifecycle` → `DoUpdate`(更新状态)→ `DoManagementCalculations` → `DoReportCalculations` → `EndOfDay` → `DoReport`(写输出)。
- **植物建模框架(PMF)**:顶层 `Plant` 类(与 APSIM 环境的接口、控制其他类);中层 `Organ`、`Phenology`、`Structure`、`Arbitrator` 类(表示器官或过程);低层 **`Function` 类**(表示通用数学/逻辑/过程/引用代码)。**所有 PMF 函数都实现 `IFunction` 接口**(单方法 `double Value(int arrayIndex = -1)`)。器官(如 `Leaf`、`Root`、`Grain`)通过 `[Link]` 持有子 Function,如 `Leaf` 持有 `[Link(Type = LinkType.Child, ByName = true)] IFunction Photosynthesis;`,只调用 `Photosynthesis.Value()` 而不关心其实现。光合由 `RUEModel : Model, IFunction` 实现,它又有 7 个子 IFunction(RUE、FT、FN、FW、FVPD、FCO2、RadnInt),`Value()` 返回 `radiationInterception * RueAct`,其中 RueAct = RUE.Value() × min(FT,FN,FVPD) × FW × FCO2——**正是 A.5 的乘法限制因子框架在代码中的体现**。`Arbitrator` 决定干物质与氮在各器官间的分配(每器官最多 Structural/Metabolic/Storage 三个生物量池),用"Priority-then-Relative-Allocation"。**关键设计收益**:作物模型(玉米、小麦、高粱)可由模型开发者在 GUI 中把通用低层 Function/Organ 类**组合(compose)**而成,无需写新代码。
- **GUI:Model-View-Presenter(MVP)模式**:Model 持有问题域数据;View 是被动(humble)的 GTK# 表单,不引用 model/presenter;Presenter 居中,告诉 View 显示什么、向 Model 要数据。中心是 `ExplorerView`(左树右面板)+ `ExplorerPresenter`;选中树节点时,Presenter 读取模型上的 `[ViewName(...)]` 与 `[PresenterName(...)]` 特性实例化对应视图/展示器。用 Command 模式(`ICommand` 的 `Do()/Undo()`、`ChangePropertyCommand`、`CommandHistory`)支持撤销/重做。设计目标:换成 Web 应用时只需重写 View。

#### C.4 DNDC:Windows 桌面应用

- 历史上是 **Windows 平台的 C++/Visual Basic 桌面应用**,必须在 Win32 平台运行;由 Changsheng Li(李长生)1992 年首次发表,UNH(新罕布什尔大学)开发维护。
- 内部按子模型组织:每个模拟年按"土壤气候→植物生长→分解→硝化与反硝化→发酵"的**固定顺序**逐日执行;读入逐日天气、土壤理化属性、植被状态先算土壤气候剖面(温度、湿度、O₂、Eh),再算作物生长、分解、硝化/反硝化、(低 Eh 时)发酵产甲烷;日末记录,年末汇总。
- 已衍生出在线/云平台(如面向中国农田的 DNDC Online),以及模块化的 Mobile-DNDC、Landscape-DNDC。

### 第四部分(D):综合——内部计算如何产生涌现/复杂系统行为

**为什么逐日迭代耦合非线性 ODE 会产生阈值/临界点/regime shift?**
- 模型里充满**非线性**:Michaelis–Menten 饱和、乘法限制因子、阈值触发(如 DNDC 反硝化在 Eh<500 mV 才启动、发酵在 Eh<−150 mV 才产甲烷、物候在 ΣGDD 跨阈值才换阶段)。这些"开关"使系统对输入的微小变化可能产生**不连续/突变**响应——例如一场大雨让厌氧气球迅速膨胀、O₂ 耗尽、NO₃⁻ 成为主导电子受体,反硝化与 N₂O 排放在一两天内爆发,这是典型的**tipping-point**行为。
- **正反馈与状态依赖**:慢碳库的积累/损失会反过来改变矿化、供氮、作物生长,跨年累积可产生**regime shift**(如长期耕作下 SOC 持续流失到新的低平衡态)。
- **等效性(equifinality)**:由于参数多、过程耦合,不同的参数组合可能产生同样好的拟合——这意味着"校准得好"不等于"机理正确",也是为什么 spin-up、独立验证、对多变量(不只产量,还有 N₂O、土壤水、SOC)同时检验如此重要。

**农学家该在哪里介入修改机理、哪里是纯软件/数值领域?**
- **机理定义层(领域科学家的战场)**:修正函数 f(T)、f(W) 的形状与参数、过程方程本身(如在极端降雨/压实下重写水分修正因子或导水率函数)、库的划分与转移系数、品种系数。在 APSIM NextGen 里,这些往往就是树中的一个 `Function` 节点或 `[Link]` 指向的可替换实现——你可以在 GUI 里把"线性温度响应"换成"β 函数三基点响应"而不碰积分引擎。在 DSSAT 里,这对应改 *.CUL/*.SPE 文件或替换一个遵守接口变量约定的模块。
- **软件/数值层(软件工程师的战场)**:时间步长选择、积分方法(欧拉 vs RK)、空间离散方案、稳定性处理、序列化/IO、并行化、GUI——这些与"机理对不对"无关,只关乎"算得准不准、快不快、稳不稳"。模块化设计的全部意义,就是**让这两层解耦**:农学家改机理函数时不必懂 MPI,软件工程师优化数值时不必懂硝化菌生理。

**给你的重写路线建议**:先实现一个 RothC(5 库、月步、欧拉)——最干净、参数公开、有官方校验数值可对照;再加 CENTURY 式的凋落物分配与质地效应;然后实现一个 RUE+Beer+GDD 的最小作物模型(上文伪代码 2);最后若要做 N₂O,再啃 DNDC 的 Nernst+M–M+厌氧气球(小时步、算子分裂)。每一步都用"先算速率、再积分、再更新"的循环骨架,把机理函数写成可替换的小函数——你就复刻了 DSSAT/APSIM 的核心设计。

## Recommendations

1. **第一步(1–2 周):实现 RothC。** 5 个库、月时间步、显式欧拉。用 Rothamsted 官方文档给出的真实计算示例(DPM 0.1533→0.1140;RPM 4.4852→4.4455;BIO 0.6671→0.6542;HUM 25.8576→25.8423)做单元测试验证你的积分正确。这是性价比最高的入门,因为参数全公开、有标准答案。
2. **第二步:加环境修正函数库。** 实现 Q10、Arrhenius、三基点 β 函数、WFPS 钟形水分曲线,做成可插拔的小函数。这一步让你直观体会"潜在→实际"的乘法框架。
3. **第三步:最小作物模型。** 用伪代码 2(GDD 物候 + Beer 截光 + RUE 生物量 + SWFAC 胁迫)。先不做土壤水,用强迫的胁迫因子;跑通后再接倾倒水桶水分平衡(DUL/LL/SAT/SWCON),这是数值最稳的方案。
4. **第四步(进阶):DNDC 的厌氧气球。** 只有当你要做 N₂O/反硝化时才上。用小时子步 + 算子分裂(分解→硝化→反硝化→发酵顺序求解),实现 Nernst 算 Eh、M–M 算速率、气球分配底物。这是最难的部分,建议直接对照 DNDC v9.5 Scientific Basis 文档的 Table 1–3 方程。
5. **架构上:从一开始就把参数外置(JSON/ini 文件)、把机理函数与积分引擎分离。** 模仿 DSSAT 六步循环或 APSIM 的 rate/integrate/update 事件顺序。若想学最现代的设计,读 `APSIMInitiative/ApsimX` 的 `Model` 基类、`[Link]` 与 `IFunction`,体会"组件树 + 反射依赖注入 + 事件"如何让模型可视化组合。
6. **验证纪律:永远用 spin-up 平衡慢碳库;永远对多个变量(不只产量)做对照;警惕 equifinality。** 改变触发阈值或决定换积分方法时,用守恒检验(质量平衡是否闭合)与步长收敛测试(减半步长结果是否变)作为判据。

**何时改变上述路线**:若你的目标系统有浅地下水位或强烈的土壤水再分布(如水稻田、湿地),倾倒水桶会失真,应转向数值解 Richards 方程(APSIM-SWIM 风格);若你发现日步下某快变过程(降雨后反硝化、热扩散)出现数值振荡,改用亚日子步或算子分裂,而非盲目换高阶 RK。

## Caveats

- **方程的版本依赖性**:DNDC 的具体方程(尤其硝化/反硝化的系数如 0.0166、0.008、0.0025)随版本演进;本报告引用的是 v9.5 Scientific Basis 文档与一篇复现该模型的论文(arXiv:1912.07782),与官方 Table 表一致,但不同版本数值可能有别。重写前请以你所用版本的官方文档为准。
- **APSIM NextGen 每日事件顺序**来自某个发行版(2020.09.09)自动生成的 Clock 文档,版本特定;`master` 分支可能有增减,但关键锚点(`DoManagement` 在日初、`DoReport` 在日末、潜在→仲裁→实际的次序)经官方文档交叉验证稳定。事件名拼写(如 `DoPotentialPlantPartioning`)保留源文档原样(确有拼写不规范)。
- **"倾倒水桶 vs Richards"无绝对优劣**:倾倒水桶更稳、参数更易得,但物理简化(已有文献指出 DNDC 这类倾倒水桶不适合精确土壤水模拟);Richards 更机理但慢且易不稳。选择取决于你的系统与数据。
- **RUE vs 光合驱动**:RUE 简单稳健、应用最广,但把光合"黑箱化",在 CO₂ 升高、极端温度等条件下机理不足;新一代机理光合(Farquhar 型)更准但参数多。
- **Q10 的局限**:恒定 Q10 不能准确描述分解的温度敏感性(尤其高温段会下降),这是单调 Arrhenius/Q10 与单峰 β 函数的根本差异;DAMM 等模型用 Arrhenius×Michaelis-Menten 的相互作用来机理化地表达高温抑制。
- **RUE 数值的口径**:Monteith(1977)的 1.4 g/MJ 是对**太阳总辐射**而言;许多模型把 RUE 定义为对 **PAR(约总辐射一半)**的效率,故数值会接近其两倍(约 2.5–3 g/MJ)。实现时务必核对你的 RUE 与辐射口径是否一致,否则生物量会差一倍。
- 本报告未逐一展开 DSSAT-CENTURY 在 CSM 内的实现细节、APSIM 的 SoilP/erosion 模块,以及各模型完整的氮素子模型——这些可按需查阅对应官方文档与源码仓库。
