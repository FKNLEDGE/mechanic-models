# Round 1：地基——守恒律 + 最简单模型

> 本章对应课程学习地图的 Round 1：「地基——守恒律 + 最简单模型」。
> 你将通过三个最简单的过程模型（Logistic 增长、RothC 土壤碳模型、AquaCrop 作物水分模型），
> 彻底吃透两个贯穿全课程的思维框架：**框架①「状态变量 + 通量 / 守恒律 / 浴缸心智模型」** 和
> **框架③「速率 → 积分 → 更新 / 数值积分 / 显式 Euler」**。

## TL;DR

- **一句话核心结论**：这三个看似毫不相干的模型（人口增长、土壤碳、作物产量）骨架完全相同——都是「状态变量每一步按 (速率 = 流入 − 流出) 更新，速率被限制因子调节」，掌握这一骨架就掌握了后续所有更难模型的钥匙。
- **两个地基框架**：守恒律 `dS/dt = Σ流入 − Σ流出`（浴缸心智模型）；数值积分 `S(t+Δt) = S(t) + (dS/dt)·Δt`（显式 Euler，"算速率→积分→更新→下一步"循环）。
- **你能动手做完**：用 Euler 跑 Logistic 并对照解析解；用 Python 复现 RothC 官方算例（精确到小数点后四位）；在 FAO AquaCrop 里跑一个玉米亏缺灌溉情景。

## Key Findings

1. **守恒律是一切过程模型的第一性原理**。`dS/dt = Σinflows − Σoutflows` 本质就是质量/能量守恒——状态量的变化率 = 进来的减去出去的。浴缸水位 = ∫(进水 − 出水) dt。
2. **计算机用"步进"代替解析解**。当驱动力（天气、灌溉）随时间变化时，连续 ODE 一般没有解析解，于是用显式 Euler 一小步一小步往前推：`S(t+Δt) = S(t) + 速率·Δt`。步长太大会不准甚至发散（数值不稳定）。
3. **Logistic 增长**（Verhulst 1838）是"速率依赖状态"的最简范例：`dN/dt = rN(1 − N/K)`，自我限制的负反馈，N=K 是稳定平衡点。
4. **RothC**（Jenkinson & Rayner 1977；Coleman & Jenkinson 1996）是最简单的土壤碳过程模型：5 个碳库各自一阶衰减，每月用精确指数解步进，三个 0–1 速率修正因子 a/b/c 调节分解速度。
5. **AquaCrop**（Steduto et al. 2009；Raes et al. 2009）是最适合初学者的作物模型：以水分驱动，`B = WP* × Σ(Tr/ET0)`，再 `Y = B × HI`，参数少、透明。
6. 三者是**同一个骨架在不同领域的化身**。

## Details

## SECTION 0：两副骨架（第一性原理）

### 框架① 状态变量 + 通量 / 守恒律：浴缸心智模型

**先问一个最朴素的问题**：一个东西的"量"为什么会变？

答案只有一个：**因为有东西进来，或有东西出去**。这就是守恒律——物质/能量不会凭空产生或消失，只会从一个地方转移到另一个地方。

把这句话写成数学语言，就是所有过程模型的"母方程"：

$$\frac{dS}{dt} = \sum \text{inflows} - \sum \text{outflows}$$

每个符号的意思（初学者请逐字读）：

- **S** (state variable，状态变量)：你关心的那个"存量"。可以是浴缸里的水量、田里的总生物量、土壤里的碳储量、种群的个体数。
- **t** (time，时间)：时间。
- **dS/dt** (rate of change，变化率)：S 随时间变化的快慢。`d` 是"微小变化量"的意思，`dS/dt` 读作"S 对 t 的导数"，直观上就是"每单位时间 S 变了多少"。
- **Σinflows** (流入通量之和)：单位时间内所有进入这个存量的速率加起来。
- **Σoutflows** (流出通量之和)：单位时间内所有离开这个存量的速率加起来。

**浴缸心智模型 (the bathtub mental model)**：

想象一个浴缸。水龙头往里灌水（inflow），排水口往外漏水（outflow）。

- 浴缸里的**水位**就是状态变量 S。
- **水位的变化速度** = 进水速率 − 出水速率。
- 如果进水比出水快，水位上升；反之下降；相等时水位不变（这叫**稳态 / steady state**）。
- 关键洞察：**当前水位本身，是过去所有"(进水 − 出水)"的累积（积分）**。用公式说：`水位(t) = 水位(0) + ∫₀ᵗ (进水 − 出水) dt`。

这就是"状态变量是通量的积分"——一个贯穿全课程的核心直觉。

**一个手算微例子**：

假设一个水箱当前有 S = 100 升水。水龙头进水 8 升/分钟，排水口出水 5 升/分钟。

- 净速率 dS/dt = 8 − 5 = +3 升/分钟。
- 1 分钟后：S ≈ 100 + 3×1 = 103 升。
- 再过 1 分钟：106 升……
- 如果某一刻把进水关到 3 升/分钟，而出水仍是 5：dS/dt = 3 − 5 = −2，水位开始下降。
- 若进水恰好 = 出水 = 5，则 dS/dt = 0，水位"冻"在原地——稳态。

注意：这里我们已经偷偷用了下一节的"步进"思想（用净速率乘以时间来推进）。

### 框架③ 速率 → 积分 → 更新：数值积分与显式 Euler

**为什么需要计算机一步步算？**

母方程 `dS/dt = ...` 是一个**微分方程 (ODE, ordinary differential equation)**。在极少数简单情况下（比如速率恒定，或 Logistic 这种特例），数学家能用纸笔求出**解析解 (analytical solution)**——一个直接告诉你"任意时刻 t 的 S 是多少"的公式。

但在真实农业系统里，速率几乎总是随时间变化的：今天下雨、明天高温、后天灌溉、再后天作物盖度变了……驱动力 (forcings) 天天不同，速率公式里塞满了随时间跳动的输入。**这种情况下一般写不出解析解**。

于是我们换一个思路：**不求"永远成立的公式"，而是从已知的起点出发，一小步一小步往前挪。** 这就是**数值积分 (numerical integration)**。

**显式（前向）Euler 法 (explicit / forward Euler method)** 是其中最简单的一种（Euler 在 1768–1770 年的《积分学原理》Institutionum calculi integralis 中首次提出，它是最基础的显式数值积分法、也是最简单的 Runge–Kutta 法）：

$$S(t + \Delta t) = S(t) + \frac{dS}{dt}\bigg|_{t} \cdot \Delta t$$

逐字解释：

- **Δt** (time step，时间步长)：你每一步往前挪多少时间。农业模型里常用 **1 天**（daily time step）或 **1 个月**。
- **dS/dt|ₜ**：在**当前时刻 t** 用当前状态算出来的速率。
- 整句话：**下一步的状态 = 当前状态 + 当前速率 × 步长**。

**"算速率 → 积分 → 更新 → 下一步"循环**（这是你会写一辈子的循环）：

1. **算速率 (compute rate)**：用当前状态 S 和当前驱动力，代入速率公式，算出 dS/dt。
2. **积分 (integrate)**：把速率乘以步长，得到这一步的增量 ΔS = (dS/dt)·Δt。
3. **更新 (update)**：S ← S + ΔS。
4. **下一步 (next step)**：t ← t + Δt，回到第 1 步。

**储蓄类比**：把 S 想成银行存款，dS/dt 是"利息+存取的净速率"。每天结一次账：今天的余额 = 昨天的余额 + 今天的净变化。日子一天天过，余额曲线就画出来了。

**步长怎么选？数值稳定性与陷阱（初学者版）**：

- Euler 假设"这一步之内速率不变"。但真实速率其实在这一步内也在变。步长越小，这个假设越接近真实，误差越小。Euler 是**一阶方法 (first-order method)**：单步的局部截断误差与步长平方 O(Δt²) 成正比，而固定时间区间内的全局误差大致与步长 Δt 成正比（步长减半，误差大致减半）。
- 步长太大会出大问题。对于衰减型方程 `dy/dt = −λy`，显式 Euler 只有在 `0 < Δt < 2/λ` 时才**稳定 (stable)**；超过 `2/λ`，数值解会震荡甚至**发散 (blow up)**——明明真实答案该平滑衰减到 0，电脑算出来却越跳越大。
  - 例：MIT 课程笔记的经典测试 `dy/dt = −10y`（λ=10），稳定要求 Δt < 0.2；取 Δt = 0.2 时解在正负之间震荡，Δt > 0.2 就振幅无界发散。
- **稳定 ≠ 准确**：步长小到不发散，也可能还不够精确，要更小才行。
- **实务建议**：日步长对大多数农业过程（作物生长、土壤水）足够；后面会看到 RothC 用了一个聪明办法——**每步用精确指数解**，所以无论步长怎样都保持为正、永不发散。

**一个手算 Euler 微例子**：

解 `dN/dt = 0.5·N`（指数增长，r=0.5），起点 N₀ = 10，步长 Δt = 1。

- 第 0 步：N = 10，速率 = 0.5×10 = 5，更新 N ← 10 + 5×1 = 15。
- 第 1 步：N = 15，速率 = 0.5×15 = 7.5，更新 N ← 15 + 7.5 = 22.5。
- 第 2 步：N = 22.5，速率 = 11.25，更新 N ← 33.75。

（真实解析解是 N = 10·e^(0.5t)，t=3 时 ≈ 44.8；Euler 给 33.75，偏低——因为 Euler 用"步首速率"代表了整步，而指数增长里速率一直在涨。把 Δt 改小，结果会更接近。这就直观展示了 Euler 的一阶误差。）

## SECTION 1：Logistic 增长（最简单的动力学模型）

### 第一性原理

指数增长（上面那个 `dN/dt = rN`）有个荒谬之处：它预测种群永远翻倍下去，撑爆地球。现实中资源有限，种群越密、竞争越烈、增长越慢。比利时数学家 **Pierre-François Verhulst 于 1838 年**在论文《Notice sur la loi que la population suit dans son accroissement》(Correspondance mathématique et physique 10:113–121) 中提出了修正（他在读了 Malthus 的《人口论》后推导，用以描述生物种群的自限性增长）：

$$\frac{dN}{dt} = rN\left(1 - \frac{N}{K}\right)$$

逐字解释：

- **N** (population / biomass，种群数量或生物量)：状态变量。
- **r** (intrinsic growth rate，内禀增长率)：资源无限时的最大相对增长速率。单位是 1/时间（如 1/天）。
- **K** (carrying capacity，环境容纳量)：环境能长期支撑的最大种群规模。这是"浴缸的最高水位"。
- **(1 − N/K)** (self-limiting factor，自我限制因子)：这是 Logistic 的灵魂。它是一个 0–1 之间的"刹车"。
  - 当 N 很小（N≪K），N/K≈0，刹车≈1，几乎不踩刹车——近似指数增长。
  - 当 N 接近 K，N/K≈1，刹车≈0，增长几乎停止。
  - 当 N = K，刹车 = 0，dN/dt = 0——稳态。

**调光开关类比**：(1 − N/K) 像一个调光旋钮。种群空旷时旋钮开到最大（增长全速），种群拥挤时旋钮拧到关（增长停）。这就是**负反馈 (negative feedback)**：状态越大，越压制自己的增长速率。

**解析解（S 曲线）**：Logistic 是少数能手解的非线性方程之一。积分后得到 S 形（sigmoid）曲线：

$$N(t) = \frac{K}{1 + \frac{K - N_0}{N_0} e^{-rt}}$$

- **N₀** (initial population，初始数量)：t=0 时的 N。
- 曲线形状：初期近指数上升（凸），过了 K/2 后增速放缓（凹），最终渐近趋向 K。拐点恰在 N = K/2（Verhulst 本人指出，d²P/dt² 在 P<K/2 时为正、P>K/2 时为负）。

虽然有解析解，**我们仍坚持也用 Euler 数值求解**——因为这是练习框架③的最佳起点，而且后面 RothC、AquaCrop 都没有这么漂亮的解析解。

### 手算例子

取 N₀ = 10，r = 0.5，K = 100，步长 Δt = 1 天。

- **第 0 天**：N = 10。速率 = 0.5×10×(1 − 10/100) = 0.5×10×0.9 = 4.5。更新 N ← 10 + 4.5 = 14.5。
- **第 1 天**：N = 14.5。速率 = 0.5×14.5×(1 − 14.5/100) = 7.25×0.855 = 6.20。更新 N ← 14.5 + 6.20 = 20.70。
- **第 2 天**：N = 20.70。速率 = 0.5×20.70×(1 − 0.207) = 10.35×0.793 = 8.21。更新 N ← 28.91。
- **第 3 天**：N = 28.91。速率 = 0.5×28.91×(1 − 0.2891) = 14.46×0.711 = 10.28。更新 N ← 39.19。

观察：随着 N 从 10 涨到接近 50（=K/2），每步增量先变大（4.5→6.2→8.2→10.3，加速）。一旦越过 K/2，增量会开始变小，最终趋近 0——速率在 N→K 时刹住。这正是 S 曲线的"先加速后减速"。

### 可运行 Python 代码（numpy + 逐行注释）

```python
import numpy as np                      # numpy：做数值数组和数学运算的标准库
import matplotlib.pyplot as plt         # 画图库

# ---------- 1. 参数设置 ----------
r  = 0.5      # 内禀增长率 r，单位 1/天
K  = 100.0    # 环境容纳量 K（最大种群）
N0 = 10.0     # 初始种群 N0
dt = 1.0      # 时间步长 Δt = 1 天
T  = 30       # 总模拟天数

# ---------- 2. 显式 Euler 数值解 ----------
steps = int(T / dt)                     # 总步数 = 总时间 / 步长
N = np.zeros(steps + 1)                 # 开一个数组存每一步的 N，初始全 0
t = np.linspace(0, T, steps + 1)        # 时间轴：从 0 到 T 均匀取点
N[0] = N0                               # 把第 0 个位置设为初始值

for i in range(steps):                  # 核心循环：一步步往前推
    rate = r * N[i] * (1 - N[i] / K)    # 第①步 算速率：dN/dt = rN(1-N/K)
    N[i+1] = N[i] + rate * dt           # 第②③步 积分+更新：N_new = N + 速率·Δt

# ---------- 3. 解析解（用于对照）----------
N_exact = K / (1 + (K - N0) / N0 * np.exp(-r * t))   # S 曲线解析公式

# ---------- 4. 画图对比 ----------
plt.plot(t, N, 'o--', label='Euler (numerical)')     # Euler 解：点+虚线
plt.plot(t, N_exact, '-', label='Analytical S-curve')# 解析解：实线
plt.axhline(K, color='gray', ls=':', label='K (carrying capacity)')  # K 水平线
plt.xlabel('time (days)'); plt.ylabel('N')
plt.legend(); plt.title('Logistic growth: Euler vs analytical')
plt.show()
```

运行后你会看到：Euler 的点几乎贴着解析解的实线，两条都呈 S 形并在 K=100 处变平。把 `dt` 调大到 3 或 4，Euler 点会开始偏离解析解（误差变大）；调到极大甚至会越过 K 来回震荡——亲手体验数值不稳定。

### 农业案例 / 应用

- **生物量/种群在容纳量处饱和**：作物群体、牧草地的总生物量、鱼塘种群，都呈"先慢、再快、后饱和"的 S 曲线。Logistic 是描述这种饱和增长的最简工具，也是资源经济学和渔业中的"主力方程"。
- **微生物生长**：Logistic 方程在 1911 年被 A. G. McKendrick 重新发现并用于描述肉汤中细菌的生长，并通过非线性参数估计进行了实验检验。
- **承载力思想的概念根源**：K 这个概念——"环境能长期支撑多少"——是生态学、放牧管理、可持续产量（最大可持续产量 MSY）的思想原点，全部源自 Logistic。Verhulst 1845 年把这条曲线命名为 "logistic"，1920 年 Raymond Pearl 与 Lowell Reed 重新发现并推广，故又称 Verhulst–Pearl 方程。

### 与框架的连接

Logistic 是**"速率依赖状态"的最简范例**：速率 `rN(1−N/K)` 同时取决于当前状态 N（越多长得越快）和限制因子（越满刹得越死）。它展示了**负反馈**和**平衡点/吸引子**两个深刻概念：

- **N = K**：稳定平衡点（stable equilibrium）。任何偏离都会被拉回——略低于 K 则正增长回升，略高则负增长回落。
- **N = 0**：不稳定平衡点（unstable equilibrium）。理论上 N=0 速率也是 0，但只要有一丁点种群，就会被指数式地推离 0、奔向 K。

记住这张图景：后面所有模型的"稳态"和"趋向平衡"都是这个道理的变体。

## SECTION 2：RothC（最简单的土壤碳过程模型）

### 第一性原理（紧凑自洽版）

RothC（Rothamsted Carbon Model，RothC-26.3）把土壤有机碳分成 **5 个库 (pools)**，每个库就是一个"浴缸"：

- **DPM** (Decomposable Plant Material，易分解植物物质)
- **RPM** (Resistant Plant Material，难分解植物物质)
- **BIO** (microbial Biomass，微生物量)
- **HUM** (Humified organic matter，腐殖化有机质)
- **IOM** (Inert Organic Matter，惰性有机质)——不分解，"焊死的浴缸"。

**一阶衰减 (first-order decay)**：每个活性库（除 IOM）的碳按其自身速率常数衰减：

$$\frac{dC}{dt} = -k \cdot C$$

- **C**：该库的碳量（t C ha⁻¹，吨碳每公顷）。
- **k** (decomposition rate constant，分解速率常数)：每年分解掉的比例尺度。RothC 的标准年值为：
  - **k_DPM = 10 yr⁻¹**（极快，几个月就没了）
  - **k_RPM = 0.3 yr⁻¹**
  - **k_BIO = 0.66 yr⁻¹**
  - **k_HUM = 0.02 yr⁻¹**（极慢，半衰期数十年）
  - IOM 不分解。

**每步精确指数解（月步长）**：RothC 不用粗糙的显式 Euler，而是对每个库用一阶衰减的**精确解**。月步长下一个含 Y t C ha⁻¹ 的活性库，月末变为：

$$C(t+\Delta t) = C \cdot e^{-a \, b \, c \, k \, \Delta t}$$

- **Δt = 1/12**（因为 k 是年速率，一个月是 1/12 年）。
- **a, b, c**：三个 0–1 之间的**速率修正因子 (rate modifiers)**——这是框架②的核心，把"潜在速率"打折成"实际速率"：
  - **a** (temperature modifier，温度因子)：冷则慢、暖则快。
  - **b** (moisture modifier，水分因子)：太干则慢。由表层土壤水分亏缺 TSMD (Top Soil Moisture Deficit) 算得。
  - **c** (plant cover / retainment factor，覆盖因子)：有作物覆盖时分解略慢（裸地分解更快）。
- 用指数解的好处：**C 永远为正、永不发散**，无论步长——这是比显式 Euler 更稳健的处理。

**分解产物的去向**：DPM 和 RPM 分解后，一部分变 CO₂（离开系统），一部分变 BIO+HUM。CO₂ 与 (BIO+HUM) 的比例由**黏粒含量 (clay content)** 决定：

$$x = 1.67\,(1.85 + 1.60\,e^{-0.0786 \cdot \%clay})$$

其中 x 是 CO₂/(BIO+HUM) 比值；分解碳中 `x/(x+1)` 变成 CO₂，`1/(x+1)` 变成 BIO+HUM。（黏粒越多，越能保护碳，越少变 CO₂。缩放因子 1.67 用于把 Rothamsted 土壤 23.4% 黏粒时的 x 定为 3.51。）

**BIO:HUM = 0.46:0.54**：进入 BIO+HUM 的那部分，固定地 46% 给 BIO、54% 给 HUM。

**IOM 初始化（Falloon et al. 1998 公式）**：

$$IOM = 0.049 \times SOC^{1.139}$$

SOC 是总有机碳（t C ha⁻¹）。这是没有放射性碳测定数据时对表层土的粗略估计。

**植物残体的 DPM/RPM 分配**：进入的植物碳按 DPM/RPM 比分到两个库。农业作物和改良草地默认 **DPM/RPM = 1.44**，即 **59% DPM、41% RPM**。（未改良草地/灌丛 0.67；落叶林/热带林 0.25，即 20% DPM、80% RPM。）

### 动手：简化 RothC 的 Python 实现 + 官方算例单元测试

```python
import numpy as np

# ---------- 1. 五个库的年分解速率常数 k (yr^-1) ----------
k = {'DPM': 10.0, 'RPM': 0.3, 'BIO': 0.66, 'HUM': 0.02}  # IOM 不分解，不入此表

def rothc_decay_step(pools, abc, dt=1/12):
    """对四个活性库做一步'精确指数衰减'。
       pools: dict，各库当前碳量 (t C/ha)
       abc:   速率修正因子乘积 a*b*c (0~1 之间)
       dt:    时间步长，月步=1/12 年
       返回:  衰减后的各库碳量"""
    new = {}
    for name in ['DPM', 'RPM', 'BIO', 'HUM']:
        # 精确解 C_new = C * exp(-a*b*c*k*dt)，保证恒正、稳定
        new[name] = pools[name] * np.exp(-abc * k[name] * dt)
    return new

# ---------- 2. 单元测试：复现 Rothamsted 官方算例 ----------
# 官方文档给定：某月 abc = 0.3561，月步 dt = 1/12
pools = {'DPM': 0.1533, 'RPM': 4.4852, 'BIO': 0.6671, 'HUM': 25.8576}
abc   = 0.3561
out   = rothc_decay_step(pools, abc, dt=1/12)

# 官方期望值
expected = {'DPM': 0.1140, 'RPM': 4.4455, 'BIO': 0.6542, 'HUM': 25.8423}
for name in expected:
    print(f"{name}: 算得 {out[name]:.4f}  期望 {expected[name]:.4f}")
    assert abs(out[name] - expected[name]) < 1e-3   # 误差小于 0.001 即通过
print("✅ 单元测试通过：成功复现 RothC 官方算例！")
```

运行后逐库打印应为：DPM 0.1140、RPM 4.4455、BIO 0.6542、HUM 25.8423，与 Rothamsted 官方文档完全吻合。这一步证明你的"精确指数步进"写对了。

**验证手算**（看懂指数）：DPM 这一步 = 0.1533 × exp(−10 × 0.3561 / 12) = 0.1533 × exp(−0.29675) = 0.1533 × 0.7432 ≈ 0.1140。✔ 速率常数 k 越大（DPM=10），衰减越猛，从 0.1533 掉到 0.1140；k 越小（HUM=0.02），几乎不动（25.8576→25.8423）。

**多月/多年循环 + 达到稳态（spin-up）**：把上面的单步包进循环，每月加入植物残体输入（按 DPM/RPM=1.44 分配）、把分解出的 BIO+HUM 按规则回填，跑几百到上千年，各库会趋于不再变化——这就是**稳态/spin-up**：流入 = 流出，浴缸水位冻住。实践中常用 RothC 的"逆运行"（inverse mode）：已知当前 SOC 和稳态条件，反推需要多少年碳输入（Coleman & Jenkinson 强调正向/逆向两种运行模式及"输入少、易获取"是 RothC 的核心优势）。

### 案例研究

- **Rothamsted 长期试验（Broadbalk，始于 1843）**：Broadbalk 冬小麦试验是世界最古老的连续田间试验之一，由 John Bennet Lawes 和 Joseph Henry Gilbert 创建，自 1843 年秋至今每年种小麦，并保存了从 1865 年起测定的土壤有机碳样品（数据集 DOI: 10.23637/KeyRefOABKsoc-02）。RothC 最初正是用 Broadbalk 的土壤数据开发和验证的。
- **不同管理下的固碳估算**：RothC 能"正向"（已知输入算 SOC 变化）和"逆向"（已知 SOC 变化反推输入）运行，被广泛用于估算施肥、秸秆还田、少耕等管理下的土壤固碳潜力，也被纳入 FAO 全球土壤固碳潜力图（GSOCseq）的方法体系。
- **热带土地利用变化（森林→牧场）**：Cerri et al. (2003, Soil Sci. Soc. Am. J. 67:1879–1887) 用 RothC-26.3 模拟巴西西亚马逊 Nova Vida 牧场（森林转牧场年代序列，森林基线 34 Mg C ha⁻¹）：原文称 "The model predicted that conversion to pasture would cause a 54% increase in the stock of organic C in the top 30 cm of soil in 100 yr"（预测转牧场后 100 年内 0–30 cm 土层有机碳增加 54%），实测 "After 88 yr, the pasture soil contained 53% more C than the forest soil"；且该模拟"未为此调参"(no adjustments were made to the model)，属独立验证。

引用：Jenkinson & Rayner (1977, Soil Science 123:298–305)（RothC 的概念前身）；Coleman & Jenkinson (1996, NATO ASI Series I, Vol. 38, pp. 237–246)（RothC-26.3 正式描述）。

### 与框架的连接

RothC = 框架① + 框架② + 框架③ 的完美合体：

- **框架①**：5 个库就是 5 个浴缸，碳在库间流动 + CO₂ 流出，严格守恒。
- **框架②**：a×b×c 三个 0–1 因子把"潜在分解速率 k"打折成"实际速率"——这就是"potential × stress"的雏形。
- **框架③**：每月步进；但用了**精确指数解**而非粗糙 Euler，所以恒正、永不发散。

## SECTION 3：AquaCrop（最适合初学者的作物模型）

### 第一性原理：水分驱动的生物量引擎

FAO 的 AquaCrop 抓住一个朴素而强大的事实：**作物长多少干物质，几乎正比于它蒸腾了多少水**。核心方程：

$$B = WP^* \times \sum \frac{Tr}{ET_0}$$

逐字解释：

- **B** (biomass，累积地上生物量)。
- **WP\*** (normalized biomass water productivity，归一化生物量水分生产力)：每蒸腾单位水产生多少生物量，且已对大气蒸发需求和 CO₂ 浓度做了**归一化 (normalized)**，因此是一个**保守的 (conservative)**、作物特异的常数。正因为归一化，WP\* 在不同地点、季节几乎不变——这是模型稳健的根基。C4 作物（如玉米）比 C3 作物高。
- **Tr** (crop transpiration，作物蒸腾)：作物通过叶片蒸腾的水（mm/天）。
- **ET₀** (reference evapotranspiration，参考蒸散)：标准草地的蒸发需求（mm/天），用 Penman-Monteith 公式算。
- **Tr/ET₀**：把蒸腾"除以当地干燥程度"做归一化，使关系跨气候可比。

**产量**：

$$Y = B \times HI$$

- **HI** (Harvest Index，收获指数)：生物量中变成可收获产量（籽粒）的比例。开花后 HI 从一个滞后期开始随时间线性上升到接近成熟。

**关键设计——用冠层盖度而非 LAI**：AquaCrop **不用**叶面积指数 (LAI)，而用**冠层盖度 (CC, canopy cover)**——地表被绿色冠层覆盖的比例（0–1）。这更直观（甚至可肉眼或遥感估计），并把**作物蒸腾 (Tr) 与土壤蒸发 (Es) 分开**：Tr 正比于被覆盖的地面，Es 正比于裸露的地面 (1−CC)。

**四个子模型（用日步长依次计算）**：

1. **冠层发育 (canopy development)**：CC 随时间生长、达到峰值 CCx、再衰老下降。
2. **作物蒸腾 (crop transpiration)**：由 CC 和 ET₀ 算 Tr。
3. **生物量 (biomass)**：由 Tr/ET₀ 累积 B（核心引擎）。
4. **产量/收获指数 (yield / HI)**：B × HI 得 Y。

**土壤水分平衡驱动胁迫**：根区被当作一个"水库"（又是浴缸！），逐日记录进出水通量（降雨、灌溉、蒸腾、蒸发、深层渗漏、径流）。当根区水分亏缺时，四个**水分胁迫系数 (Ks, 0–1)** 启动，分别抑制：(a) 叶片扩展→减小 CC、(b) 加速衰老、(c) 关闭气孔→减少 Tr、(d) 影响 HI。

引用：Steduto et al. (2009, Agron. J. 101:426–437)（概念与原理）；Raes et al. (2009, Agron. J. 101:438–447）（算法与软件）。

### 概念性走查例子

设想一季玉米：

1. **播种—出苗**：CC 很小，地面大半裸露，水主要从土壤蒸发 (Es) 走掉，Tr 很小，B 几乎不长。
2. **快速生长**：CC 迅速上升接近 CCx（接近全覆盖），Tr 随之变大，每天 `WP* × Tr/ET₀` 累加，B 快速积累。
3. **若遇干旱**：根区水分亏缺 → Ks 下降 → 先抑制叶扩展（CC 长不上去）、再关气孔（Tr 减少）→ 当天 B 增量减少。**水分胁迫通过减少 CC 和 Tr 来削减生物量**（注意：除非极严重，胁迫几乎不改变 WP\* 本身——胁迫的影响"几乎全部"体现在 Tr 的减少上）。
4. **生殖—成熟**：开花后 HI 线性上升，把累积的 B 转化为籽粒产量 Y = B × HI。若关键期（开花/灌浆）缺水，HI 受损，产量下降。

### 动手 / 案例研究

**AquaCrop 是 FAO 免费下载的工具**（Windows 程序，2009 年 1 月首发 v3）。初学者跑一季玉米的流程：

1. 准备四类输入文件：气候（最高/最低气温、降雨、ET₀）、作物（玉米默认参数）、土壤（质地、田间持水量等）、管理（灌溉、施肥）。
2. 用内置玉米默认参数和示例气候，跑"完全灌溉"基准情景，看 CC、B、Y 曲线。
3. **亏缺灌溉 (deficit irrigation) 情景**：把灌溉量减到例如 ET 的 80%/70%/50%，重跑，比较产量和耗水。AquaCrop 可在每个时间步暂停以研究水分输入变化的影响，特别适合制定亏缺灌溉策略。

**真实验证案例**：

- **玉米**：Hsiao et al. (2009, Agron. J. 101:448–459) 用美国加州 Davis 6 年玉米田间数据（4 个品种）率定 19 个保守参数。原文：模拟与实测之间"the largest deviation … was 22% for biomass, and 24% for grain yield"，而 13 个处理中有 11 个的 Willmott 一致性指数 d ≥0.98（冠层盖度）、≥0.97（生物量）——即生物量随时间的进程模拟得相当好。玉米的 WP\* 取 "33.7 g (biomass) m⁻², function of atmospheric CO2"（归一化到 2000 年 CO₂）。
- **棉花**：García-Vila et al. (2009, Agron. J. 101:477–487) 把 AquaCrop 与经济模型结合优化西班牙南部棉花亏缺灌溉。原文：最大利润出现在施灌水量 (AIW) "between 540 and 740 mm, depending on the climatic scenario"，但当 AIW 超过 300–350 mm 时利润已接近最大值的 95% 以上——说明节水空间很大。
- **藜麦 (quinoa)**：Geerts 等在玻利维亚高原的研究——见下"案例聚焦"。
- **苔麸 (tef)**：Araya et al. (2010, Field Crops Res. 116:196–204) 在埃塞俄比亚北部率定 AquaCrop，发现苔麸籽粒水分利用效率随开花后补充灌溉从 0 增到 95 mm 而提高，而生物量水分利用效率则相反下降。

**案例聚焦——藜麦亏缺灌溉（玻利维亚南部高原）**：Geerts et al. (2009, Agron. J. 101:499–508) 在海拔 4000 m (4000 masl) 的玻利维亚高原对藜麦做了 3 年（2004–2007）田间试验，"under different watering conditions (from rain fed, RF, to full irrigation, FI)"，并用 AquaCrop 模拟。一个反直觉的关键结论：生物量水分生产力（g m⁻²）在完全灌溉下比雨养/亏缺灌溉**低约 9%**（很可能因严重养分耗竭），说明在该系统盲目多灌并不划算。配套的 Geerts et al. (2008, Agric. Water Manage. 95:909–917) 进一步指出：附加灌溉只有在满足约 55% 作物需水之上才显著有效，且该地区藜麦亏缺灌溉"should be considered with precaution"（因水资源有限且常含盐），最优策略是把有限的水集中用在敏感生育期（开花与灌浆初期）。

**刻意保持少参数**：AquaCrop 相比其他作物模型 "maintains an optimal balance between accuracy, robustness, and simplicity, and requires a relatively small number of model input parameters"，用相对少的保守作物参数、分四步模拟，使建模过程透明、易懂——这正是它对初学者友好的原因。

### 与框架的连接

AquaCrop = 框架① + ② + ③：

- **框架①**：根区土壤水是一个浴缸——水分进（降雨、灌溉、毛管上升）减去出（蒸腾、蒸发、渗漏、径流）。
- **框架②**：水分胁迫系数 Ks（0–1）把潜在冠层/蒸腾打折成实际值——又是"potential × stress"。
- **框架③**：逐日步进，依次算冠层、蒸腾、生物量、产量。

## SECTION 4：三者的共性（统一图景）

虽然分属三个领域（种群、土壤碳、作物水分），三个模型是**同一副骨架**：

> **状态变量，每一步按 (速率 = 流入 − 流出) 更新，速率被限制/胁迫因子调节。**

| 维度 | Logistic 增长 | RothC | AquaCrop |
|---|---|---|---|
| **状态变量 S** | 种群/生物量 N | 5 个碳库 DPM/RPM/BIO/HUM/IOM | 根区土壤水；冠层 CC；生物量 B |
| **支配方程** | dN/dt = rN(1−N/K) | dC/dt = −k·C（各库一阶衰减）+ 库间转移 | 水量平衡 + B = WP*·Σ(Tr/ET₀) |
| **速率** | rN（潜在）× 刹车 | k·C（潜在分解） | 潜在蒸腾 / 生物量增量 |
| **限制/胁迫因子** | (1 − N/K) 自我限制 | a(温)×b(水)×c(覆盖)，均 0–1 | Ks 水分胁迫，0–1 |
| **时间步长** | 任意（示例日步） | 月步（精确指数解） | 日步 |
| **平衡行为** | N→K 稳定，N=0 不稳定 | 流入=流出时各库稳态（spin-up） | 季末产量；水库可达准稳态 |

读懂这张表，你就掌握了过程建模的"元结构"。后面更难的模型（DNDC、CENTURY、APSIM、DSSAT）无非是：**更多的库、更多的胁迫因子、更复杂的速率公式、更多耦合的浴缸**——骨架不变。

## Caveats（重要提醒）

- **简化与教学取舍**：本章的 Python 实现是**教学简化版**。完整 RothC 还包含库间碳的回填转移（分解出的 BIO+HUM 要按比例分回各库）、TSMD 水分因子的逐月计算、放射性碳年龄等，本章单元测试只验证"单步衰减"这一最核心环节。完整 AquaCrop 远比 `B=WP*·ΣTr/ET₀` 复杂（含冠层动态、气孔、根系、盐分、肥力胁迫等）。
- **WP\* 数值**：玉米的 WP\* 在 Hsiao et al. (2009) 与 FAO 参考手册中作为 C4 作物取约 **33.7 g/m²**（归一化到 2000 年 CO₂；C4 一般 30–35 g/m²，C3 一般 15–20 g/m²），但实测会随种植方式、品种变化——文献报道范围从 Ran et al. (2018) 膜下制种玉米的 **20.9 g/m²** 到 Wang et al. (2022, Agriculture 12(1):97) 膜下滴灌密植的 **37.81 g/m²** 不等。可见"保守参数"也只是"相对保守"，并非绝对常数。
- **RothC 速率常数可被率定**：标准 k 值（10/0.3/0.66/0.02）来自 Rothamsted 田间试验，但在不同土壤（如火山灰土 andosol、水稻土、干旱区）常需重新率定，文献中 HUM 的 k 被改到 0.005–0.01（而非 0.02）的例子不少。把它们当"通用真理"会出错。
- **Euler 的局限**：本章用显式 Euler 主要为教学直观。真实工程中对刚性（stiff）或振荡问题，显式 Euler 可能需要极小步长或会发散，届时应换隐式方法（如后向 Euler，无条件稳定）或更高阶方法（如 Runge–Kutta）。RothC 用精确指数解正是为绕开这一陷阱。
- **案例数字的来源层级**：森林→牧场 +54%、棉花 540–740 mm 等数字来自具体研究的特定地点与假设，不可外推为普适结论。藜麦"完全灌溉生物量 WP 反低约 9%"被归因于该试验点的养分耗竭，是该系统的特殊性而非普遍规律。另需注意：Geerts et al. (2009) 主要是模型率定/验证论文，其藜麦亏缺灌溉的"操作性 kg/m³ 水分生产力图表与灌溉时刻表"实际出自后续的 Geerts, Raes & Garcia (2010, Agric. Water Manage. 98:213–216)。
